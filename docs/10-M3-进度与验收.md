# M3 进度与验收（世界书注入 → Prompt 调试 → 卡高级编辑 → ST 预设）

> 目标：让「角色卡 + 世界书」这套 ST 的核心配置真正影响回复，而不是只做展示。
> 本文只记 **M3 步骤 1（世界书绑定与注入）**；步骤 2–4 完成后追加。

## 1. 本步范围（0.8.0 / DB v8）

- 世界书**绑定**：角色级默认 + 会话级覆盖。
- 世界书**注入**：`:core` 纯逻辑注入引擎，接入 `ChatEngine` 的 prompt 组装。
- 详情页：把「世界书（N 条）」从只读预览改成**绑定对话框**（卡内嵌只读 + 库中世界书勾选）。
- 迁移与测试：DB v7 → v8（纯增量列）、迁移测试覆盖 1→8、注入引擎单测。

**不做**（后续步骤）：递归扫描、sticky/cooldown、向量召回、token 级预算（当前是字符预算）、Prompt 调试面板。

## 2. 数据模型

| 表 | 新增列 | 语义 |
| --- | --- | --- |
| `characters` | `linkedWorldBookIdsJson TEXT NOT NULL DEFAULT '[]'` | 角色默认绑定的世界书 id 数组；任何会话未覆盖时生效 |
| `conversations` | `worldBookIdsJson TEXT`（NULL 允许） | 会话级覆盖：`NULL` = 继承角色；`[]` = 显式不启用；`[1,2]` = 只用这两本 |

解析优先级（`CharacterRepository.effectiveWorldBookIds`）：

```
会话存在且有非 NULL 覆盖 → 用覆盖
否则                    → 用角色默认绑定
```

## 3. 注入引擎（`:core`）

`core/src/main/kotlin/com/teatalk/core/worldinfo/WorldInfoInjector.kt`：

- 入口 `select(entries, scanText, charBudget)`：跑一遍关键词/常量匹配（复用 `WorldInfoEngine`），按 `order` 降序、字符预算截断。
- `render(entry)`：`【comment】\ncontent`，便于模型与后续调试面板识别来源。
- 位置映射（ST `position`）：

| ST position | 含义 | TeaTalk 落点 |
| --- | --- | --- |
| 0 | 角色定义之前 | 并入 system prompt 的 `[世界书·角色前]` 段 |
| 1 | 角色定义之后 | 并入 system prompt 的 `[世界书·角色后]` 段 |
| 2 | Author's Note 顶部 | 历史最前面插一条 `system` |
| 3 | Author's Note 底部 | 本次用户消息之前插一条 `system` |
| 4 | 按 `depth` 插入历史 | 倒数第 `depth` 条之前；`role` 0/1/2 → system/user/assistant |

- `injectHistory(history, insertions)`：`depthFromEnd` 语义为「距末尾第几条之前」；同深度按 `order` 降序；超出历史长度的深度（AN 顶部）放到最前。
- 注释：`WorldInfoParser.fromStandalone(json)` 解析 D6 导入的独立世界书文件（`{entries:{...}}`）。

`ChatEngine` 中的接线顺序：

1. 解析卡（`Dispatchers.Default`）→ 卡内嵌 `card.worldBook`。
2. 取生效绑定 → `worldBookEntries(ids)` 批量解析库中世界书。
3. 合并去重（同 `uid+comment` 以内嵌为准）。
4. 扫描文本 = 最近 3 条消息拼接（兼顾「主关键词命中」与 ST 的最近 N 条行为）。
5. `select` → 前/后段进 system prompt；position 2/3/4 插入历史。
6. 日志：`Prompt worldbook.inject entries=… activated=… chars=… bound=…`。

## 7. 已知限制与下一步

- **字符预算**而非 token 预算；超长条目按段截断（system prompt 每段 6000 字符）。
- 不支持递归激活（A 命中后带出 B）、sticky/cooldown、向量检索。
- 会话级覆盖只有数据层/API，UI 入口待做。
- 扫描文本固定为最近 3 条，ST 的 `scan_depth` 设置未暴露。

M3 后续：步骤 2 Prompt 调试面板（只读、脱敏、可复制）、步骤 3 角色卡高级编辑（system_prompt / post_history_instructions / alternate_greetings / mes_example）、步骤 4 ST 预设导入。

## 8. 步骤 1 审阅修复轮（0.8.1）

> 四专家审阅（Software Architect / UX Architect / UI Designer / Reality Checker）后按 P0 修复，详见 `docs/reviews/m3/SUMMARY.md`。

### 8.1 注入语义（会改变输出，务必知道）

| 项 | 修复前 | 修复后（与 ST 一致） |
| --- | --- | --- |
| at-depth `depth=0` | 最后一条消息**之前** | 最后一条消息**之后** |
| `depth ≥ 历史长度` | 塞到历史最前（问候语之前） | 夹到最前（`index=0`），即问候语之前——语义等于「很早之前」 |
| AN 顶/底 | 顶=最前、底=贴底 | 都锚在 `AN_DEPTH=4`；同点顺序 `AN顶 → at-depth → AN底` |
| `order` 渲染 | 降序直接 join | **升序**（ST `order 999→1` + `unshift`） |
| `position 5/6/7` | 激活、吃预算、丢弃 | `select` 阶段就过滤，日志记 `unsupported=N` |
| 未知 position 字符串 | 回落 0（混进 system prompt 开头） | `UNSUPPORTED_POSITION=-1`，注入时丢弃 |
| 跨书去重 | `(uid, comment)`（uid 是书内命名空间） | 源内 `(uid, comment)`；跨源按 `content` 去重 |

### 8.2 预算与解析

- 世界书预算单点：`ChatEngine.MAX_WORLD_BOOK_CHARS = 8000` 传入 `select`；system prompt 内不再对世界书块二次 `take()`。
- 解析统一：`WorldInfoParser.fromAny(json)` 同时支持 `data.character_book`、顶层 `entries`（对象/数组）与**根数组**；`fromCard`/`fromStandalone` 均为其别名。
- `linkedWorldBookIdsJson` 解析抽成 `WorldBookIds`（宽容四态，坏数据当未绑定），5 条单测覆盖。

### 8.3 UI

- 绑定对话框改为 **ModalBottomSheet + 草稿态**：勾选只改草稿；`Cancel` 不回滚已保存值；`Save` 才写库并在详情页弹「世界书绑定已保存」；未改动时 Save 置灰。
- 计数口径统一：胶囊 `世界书 · 7 条`；标题 `生效 7 条 · 已绑定 1 本`；库标题 `1 本 · 已勾选 1`（zh）/ `1 book · 1 selected`（en），全部用 plurals。
- 胶囊描边 `outlineVariant` → `outline`（对比度 1.39:1 → 3.88:1）。
- 库空态提供「去导入世界书」直达入口；勾选行仅 Checkbox 可交互（TalkBack 不再出现两个可勾选节点）。
- 绑定不再写 `characters.updatedAt`（不改「最近」排序）。

### 8.4 验证

- 单测：`:core:test` 59 条（含新增 depth 夹取/空历史/升序/位置过滤/根数组/未知 position）+ `:app:testDebugUnitTest` 新增 `WorldBookIdsTest` 5 条。
- AVD 实测：`World book · 7 entries` → 打开面板 `7 entries active · 1 book bound` → 取消勾选后 `Cancel` 胶囊仍为 7 → 再勾选并 `Save` → 胶囊 `4 entries` + snackbar「World book binding saved」。
- 迁移测试：改名 `migrate_1_to_current_*`，新增「无孤儿消息」「按角色归属」断言。

### 8.5 遗留

- 会话级覆盖仅数据层/API，无 UI 入口。
- `position 5/6/7`（示例消息/作者注释）与递归激活、sticky/cooldown、token 预算仍不做。
- 根目录 `schemas/` 为过期副本，Plan 下轮清理。


## 9. 修复轮 2（0.8.1 四专家复核后，0.8.2）

本轮针对 0.8.1 的四专家复核结论做修复，按批次 A–D 执行。

### 9.1 批次 A：数据正确性
- **跨书去重不再吞书**：新增 `data/WorldBookMerger.kt`（`SourcedWorldInfoEntry`/`merge`），去重键改为 `(sourceId, uid)`，并保留每条的 `sourceId` 用于日志；补充单测覆盖「同名不同书」「uid 相同但来源不同」。
- **条目级预算**：`WorldInfoInjector.InjectOptions` 增加 `maxChars`（来自 `ChatEngine.MAX_WORLD_BOOK_CHARS`），此前只按条数截断，会让超长条目绕过上限；预算裁剪改为逐条字符累加。
- **日志口径**：`worldbook.inject entries= activated= chars= unsupported= bound=` 五项与实现一致，`unsupported` 统计未知 position/role 的条目。

### 9.2 批次 B：迁移测试与数据安全
- `app/src/androidTest/assets/com.teatalk.xs.data.db.TeaTalkDatabase/` 补齐 1..8 的 schema 副本（v8 世界书绑定列入迁移校验）。
- `TeaTalkDatabaseTestV8` 增加 `migration8_preserves_world_book_ids`：v7→v8 后 `linkedWorldBookIdsJson` 原样保留。
- `:app:connectedDebugAndroidTest` 3/3 通过（模拟器；会清空 App 数据，文档已注明）。

### 9.3 批次 C：UI 与证据
- **删除世界书级联**：`CharacterRepository.deleteWorldBook` 在删除前清理所有角色的 `linkedWorldBookIdsJson` 引用，不再留下悬空绑定；实测删除后详情页 `World book · 4 entries`、弹层显示 `4 entries in scope · 0 books bound`。
- **横屏弹层**：绑定面板的 `ModalBottomSheet` 改为固定「头/滚动体/操作区」三段，`weight(1f)` 限制列表高度，横屏 2340×1080 下 Cancel/Save 与列表同时可见可滚。
- **文案与空库**：头部改为 `%d entries in scope · %d books bound`（计数与绑定数分开），空库 CTA 移到列表上方，`worldbook_entry_count` 复数（zh/en 各补 one/other）。
- **a11y**：条目行由「空白复选框」改为整行 `toggleable` + `semantics(mergeDescendants)`，`Checkbox` 不再独立进无障碍树；行节点可点击、可勾选（dump 已确认）。
- **描边**：CTA 未绑定时 `outline` 常态、已绑定 `onSurfaceVariant` + 半粗体，但仅当列表变化时重绘快照（详见 README 风险）。
