# 22 - 批量管理（0.22.0）

## 目标

SillyTavern 用户常一次导入几十张卡，逐张「收藏 / 删除」不现实。0.22.0 提供最小可用的批量操作：一次选中多张，批量收藏 / 取消收藏 / 删除。

## 范围取舍

只做「批量选择 + 批量操作」，**不新建分组表**：

- 角色列表已有标签筛选（`TagChip` + `CharactersViewModel.selectTag`），标签足以承担「分组」语义；
- 新增分组表需要 DB 迁移 + 分组管理页 + 卡片拖拽，成本远高于收益；
- 真正的自定义分组（可命名、可排序）留到后续版本按需求评估。

## 交互

| 步骤 | 行为 |
| --- | --- |
| 进入 | 顶栏 ⋮ 菜单 →「批量管理」 |
| 选择模式 | 标题变「已选 N」，右侧「全选 / 取消」；卡片左上出现圆形勾选；新建 / ⋮ / 导入隐藏 |
| 选中 | 点卡片切换选中；「全选」一键选中当前筛选结果（再点清空） |
| 批量操作 | 底部条：收藏 / 取消收藏 / 删除（未选中时禁用） |
| 删除 | 弹确认「将删除 N 张角色卡及其聊天记录，无法撤销」，确认后退出选择模式 |
| 退出 | 顶部「取消」 |

实现要点：

- `CharactersScreen.kt`：`selecting` / `selection` / `batchDeletePending` 三个 `remember` 状态；`CharacterCard` 新增 `selectable`、`selected`；`BatchActionBar` 用 `NavigationBar` 三按钮。
- `CharactersViewModel.kt`：`setFavoriteAll(ids, favorite)` 只对「状态确实需要变」的卡发写请求；`deleteAll(ids)` 复用 `CharacterRepository.delete`（与单卡删除同语义，连同聊天记录）。
- 结果通过既有 `_message` → `SnackbarHost` 反馈（「已收藏 N 张」/「已取消收藏 N 张」/「已删除 N 张」）。

## 已知限制

- 批量操作作用于「当前筛选结果里可见的卡」；跨标签选择需要先进「全部」再选。
- 删除不可撤销（与单卡删除一致）；批量删除没有提供回收站。
