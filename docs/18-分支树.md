# 0.20.0 分支树

> 状态：已实现并在真机验收（HUAWEI TAS-AN00 / Android 12）。
> 目标：任何一条 assistant 回复都能「从此分支」——保留该点之前的历史、另起一个会话，原会话不动。

## 目标

- 社区常见用法：一条回复读起来不对，用户想回到那个点重走一遍，而不是清空整段历史。
- 要求：原会话完全不被修改；分支会话可继续聊天、可再分支；列表里能一眼看出这是分支。

## 实现

### 数据层（DB v13）

`conversations` 增加三列，全部**可空**（`ALTER TABLE … ADD COLUMN … NOT NULL` 在 SQLite 必须带
`DEFAULT`，而 Room 校验对 `DEFAULT` 很敏感，0.18.1 已经踩过一次，这里直接给可空列避开）：

- `parentConversationId`：来源会话 id（null = 根会话）
- `forkMessageId`：从哪条消息分出来的（null = 根会话）
- `forkLabel`：用户给分支起的名字（null = 用来源会话标题）

`MIGRATION_12_13` 只做三条 `ALTER TABLE`，日志 `Db db.migrate from=12 to=13`。

### 纯逻辑（可单测）

`apps` 层新增 `BranchFork`：

```kotlin
data class ForkPlan(val conversation: ConversationEntity, val messages: List<MessageEntity>)

object BranchFork {
    const val MAX_LABEL = 40
    fun plan(source, messages, upToMessageId, label, now): ForkPlan?
}
```

规则：按 `(createdAt, id)` 排序；目标消息不存在则返回 null；只保留「不晚于目标」的前缀；新会话
`title = label ?: source.title`、`parentConversationId = source.id`、`forkMessageId = 目标 id`；
消息 `id/conversationId` 归零交给 Room 重新分配（其余字段原样复制，含群聊 `speakerId`）。

`CharacterRepository.forkConversation()` 只负责 IO：读原会话 + 全部消息 → `BranchFork.plan` →
`insertWithMessages`（一个事务）→ 群聊再复制 `conversation_members`。

### UI

- 气泡长按菜单新增「从此分支」（在「复制」之后），点开「从此分支」对话框（可填分支名，限 40 字）。
- 创建成功后自动跳到新会话（`onOpenConversation`），并提示失败原因（创建失败才显示）。
- 会话列表对 `parentConversationId != null` 的行显示「分支」小标签。

## 取舍与已知限制

- **不复制会话级 prompt 覆盖、世界书绑定**：分支沿用角色的设置，避免「分支带着旧覆盖跑偏」；
  如果要做「分支独立设置」，应作为独立开关，而不是默认继承。
- 分支会话的消息保留**原始时间戳**，所以列表时间显示的是最后一条消息的时间（例如 `11-02`），
  不是分叉时间——这是有意为之：分支是「那段对话的另一条时间线」。
- 分支再分支是允许的（`parentConversationId` 指向分支），但没有做树形视图；列表目前是扁平的，
  靠「分支」标签区分。树形 UI 留到后续版本，先保证数据里有父子关系。
- 删除来源会话不会级联删除分支（分支已经是独立会话）；删除分支也不影响来源。
- 长按的是 assistant 气泡；user 气泡暂不提供分支入口（从 user 消息分叉等价于「重发这一句」，
  语义更像「重新生成」，等交互设计清楚再开）。
