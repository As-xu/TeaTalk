> 版本基线：0.11.0（M4-1 完成）/ 2026-10-31

## 1. 为什么先做 M4-1（聊天 JSONL）

M4 的验收条件是「把 ST `data/default-user` 整个目录导进来，聊天记录可继续对话」。
其中**聊天记录**的落点是 ST 的 `chats/<角色>/<会话>.jsonl`，它同时是最容易被用户感知的迁移路径：

- 角色卡只需要文件（PNG / JSON / CHARX），已有导入；
- 世界书有独立的导入/绑定；
- 唯独聊天记录没有出口，用户换 App 等于丢掉全部对话。

所以 M4-1 先补「单会话 JSONL 导出 + 导入」，给后续 M4-4（整目录导入）打地基。

## 2. 格式（对齐 ST）

`ChatJsonl` 直接复用 ST 的磁盘格式（`SillyTavern/src/endpoints/chats.js` 的写盘逻辑）：

- 第 1 行：`{"chat_metadata":{...},"user_name":"unused","character_name":"unused"}`
- 之后每行一条消息：`name / is_user / is_system / send_date / mes / extra / swipe_id / swipes / swipe_info`
- `swipes` 是这一轮的全部候选回复，`swipe_id` 是当前选中的下标；`extra.api/model` 是生成来源。

实现：`app/src/main/java/com/teatalk/xs/data/ChatJsonl.kt`

- `parse(text)`：只依赖上表字段；头行/空行/坏行不会让整次导入失败（坏行计入 `skippedLines`）；`send_date` 用 ISO-8601 解析，失败回退当前时间。
- `export(characterName, messages)`：写出 ST 形状；多版本回复写 `swipes/swipe_id/swipe_info`，单版本也写成单元素数组（与 ST 一致）。

## 3. 行为

| 入口 | 位置 | 行为 |
| --- | --- | --- |
| 导出 | 聊天页 ⋮ →「Export chat (JSONL)」 | 读当前会话全部消息 → 写 `cacheDir/export/teatalk-chat-<ts>.jsonl` → 系统分享（FileProvider，只暴露 `cache/export/` 子目录） |
| 导入 | 聊天页 ⋮ →「Import chat (JSONL)…」 | SAF 选文件 → 新建一条会话写入全部消息 → 自动跳到新会话 |

导入映射：

- `is_user` → `role=user`；`is_system` → `role=system`；其余 → `role=assistant`；
- `swipes` 长度 > 1 时写 `variantsJson` + `variantStatusJson`（全部 complete）+ `selectedVariant=swipe_id`；
- `extra.api → providerName`、`extra.model → model`（旧消息的「谁生成的」可追溯）；
- 新会话标题用 `chat_import_title`（「导入的聊天 / Imported chat」），避免和原会话标题混淆；
- 单文件上限 32M 字符（防误选大文件），解析出 0 条消息视为失败并提示。

## 5. 踩坑与决策

- **FileProvider 崩溃**：导出文件放在 `cacheDir/export/` 子目录，但 `res/xml/file_paths.xml` 只声明了 `logs/`，分享时抛
  `IllegalArgumentException: Failed to find configured root` → 增加 `<cache-path name="chat_export" path="export/"/>`。
  决策：**只暴露具体子目录**，不把整个 cacheDir 交给分享目标。
- **不写死 ST 的副作用字段**：`chat_metadata` 里的 `timedWorldInfo/note_*` 等导出时给空对象，导入时忽略；这些是 ST 的扩展状态，不是对话语义。
- **标题不沿用原会话名**：导入一律新建会话（不合并），标题用固定文案，避免和原会话同名造成误解。

## 7. M4-4 整目录导入（0.11.1）

入口：**我的 → Import from SillyTavern…**（`OpenDocumentTree`，SAF 目录授权）。

支持的目录结构（大小写不敏感）：

```
data/default-user/
  characters/*.png|*.json|*.charx   -> 角色卡
  worlds/*.json                     -> 独立世界书
  chats/<角色名>/*.jsonl            -> 该角色的聊天（按角色名匹配）
```

- 根目录没有 `characters/` 时，把根目录里的卡文件当角色卡（只导角色也顺手）。
- 聊天按**文件夹名 == 角色名**匹配；匹配不到的 jsonl 计入「跳过」，不猜身份。
- 别的 ST 内容（settings/themes/presets/group chats）不在这个入口静默处理，各自有单独入口。
- 结束后弹「导入完成」对话框：角色卡 / 世界书 / 聊天 各自数量 + 失败数 + 跳过数。

实现：`app/src/main/java/com/teatalk/xs/data/StDirectoryImporter.kt`，直接用 `DocumentsContract` 查 SAF 树
（不引 `documentfile` 依赖：本机拉新依赖会被代理拦住，而这里只需要列子项 + 名字/是否目录）。

验收（AVD，API 34）：把 `characters/golden-aster.json`、`worlds/world_test.json`、
`chats/Aster/chat_st_sample.jsonl` 放进 `Download/st-import/`，选目录授权后：

- 对话框：`Characters: 1 (failed 0)` / `World books: 1 (failed 0)` / `Chats: 1 conversations (skipped 0)`；
- 日志：`I/Import st.dir cards=1/0 worlds=1/0 chats=1/0`；
- 落库：`characters` 2 行（Seraphina + Aster）、`world_books` 1 行、`conversations` 3 行，
  其中 `title=chat_st_sample, characterId=Aster`（按文件夹名正确挂到导入的角色）。

截图：`docs/screenshots/m4/04-st-folder-picker.png`、`05-st-import-summary.png`。

未做：group chats、settings/presets 迁移、导入前 dry-run 预览、同名卡去重策略（目前重复导入会产生重复角色，与单卡导入一致）。

## 8. M4-2 世界书条目编辑（0.11.2）

入口：**我的 → World books → 点一本 → 条目行尾 Edit**。

可编辑字段：标题、关键词、次要关键词、内容、顺序、深度、位置（7 档）、角色（system/user/assistant）、启用、常驻、次要关键词需命中。

实现要点：

- `app/src/main/java/com/teatalk/xs/data/WorldBookEntryPatch.kt`：**直接在原始 JSON 上打补丁**，
  不反序列化再序列化。原因：`WorldInfoEntry` 只保留我们认识的字段，整轮写回会把 ST 的
  `automation_id / group_weight / …` 全抹掉。补丁只改被编辑的字段，其余原样保留。
- 同时支持两种结构：ST 独立文件（`entries` 为 `{uid: {...}}` 对象，也接受数组）与角色卡内嵌
  （`data.character_book.entries[]`）。卡内嵌把 `position/depth/role` 写进 `extensions`（与 ST 一致，
  解析器也是 extensions 优先）。
- 顺手修了一个真 bug：ST 独立文件的关键词是逗号字符串（`"key": "茶, tea"`），解析器原来把它当成
  **一个**关键词（靠 substring 命中凑巧能用）；现在按逗号拆成多个（`core/.../WorldInfo.kt` 的
  `keyList()`），数组形态保持兼容。

测试：`app/src/test/java/com/teatalk/xs/data/WorldBookEntryPatchTest.kt`（3 条：ST 对象补丁保留未知字段、
卡内嵌数组补丁写 extensions、不认识的形态返回 null）。

验收（AVD）：编辑「茶馆设定」的标题为 `Edited`、关键词保持 `茶, tea` → Save → 列表刷新同名；
DB `world_books.entriesJson` 中 `comment` 已改、其余字段与另一条条目原样保留。

截图：`docs/screenshots/m4/06-worldbook-entry-edit.png`。

## 9. M4-3 新建角色（0.11.2）
