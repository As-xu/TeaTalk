# 24 - 云备份（WebDAV，0.24.0）

## 目标

把「备份与导出」从「手动生成 zip、再手动放到网盘」变成应用内闭环：填一次 WebDAV 账号，之后一键上传、随时从远端列表恢复；换机或重装时不用先找回文件管理器里的 zip。

## 范围取舍

- **只做 WebDAV 协议**（坚果云 / Nextcloud / 群晖 / InfiniCLOUD 等）：一个协议覆盖多数网盘，不接各家的私有 OAuth。
- **复用既有 zip 格式**：`BackupRepository.export()/restore()` 已经是「角色卡 + 世界书 + 会话 + 消息 + 头像」的完整快照，云备份只负责搬运，不新增格式。
- **整包上传 / 整包导入，不做自动合并**：合并需要逐条冲突策略（同名但内容不同怎么办），语义不清，先不做。
- 远端保留最近 **10** 份、恢复前本地快照保留 **3** 份：够回溯，又不会把手机或网盘塞满。
- 不做定时自动备份：后台调度需要 WorkManager + 电池优化豁免，留给后续版本。
- 备份**不加密**（与「数据只存本机 / 用户自持」一致）；UI 明确提示用「应用密码」，不要用主账号密码。

## 交互

| 步骤 | 行为 |
| --- | --- |
| 入口 | 我的 → 云备份（WebDAV） |
| 配置 | 服务器地址 / 用户名 / 密码（应用密码）/ 远端目录，默认目录 `TeaTalk` |
| 密码 | 只存 EncryptedSharedPreferences；已保存时输入框留空 = 不修改，下方常驻「已保存 ****，留空则不修改」 |
| 测试连接 | PROPFIND Depth 0；成功 Snackbar「连接成功」，401/403 提示「连接失败：401」 |
| 立即备份 | 上传 `backup-yyyyMMdd-HHmmss.zip`，Snackbar「已上传 backup-….zip（7.1 MB）」，并自动刷新列表 |
| 远端列表 | 只列 `backup-*.zip`，按时间倒序，显示名字与大小；右上角刷新 |
| 恢复 | 点某一行或「恢复」→ 确认弹层（写明「先留本机快照；同名跳过，不覆盖」）→ Snackbar「已恢复 X 张卡 · Y 本世界书 · Z 个会话，跳过 N 条已存在」 |
| 清除 | 配置区右侧「清除」：清空地址/用户名并删除加密密码 |

## 实现要点

- `data/model/SecretStore.kt`：新增通用命名密钥 `putNamed/getNamed/hasNamed/removeNamed`（`named_secret_<name>`），WebDAV 密码用 `named_secret_webdav_password`；provider key 仍是 `provider_key_<id>`，互不影响。
- `data/model/AppPrefs.kt`：`webDavUrl` / `webDavUser` / `webDavDir`（默认 `TeaTalk`，写入时去掉首尾 `/`，空则回落默认）。
- `data/net/WebDavClient.kt`（新增）：OkHttp + Basic Auth，四个方法 `propfind / mkcol / put / get / delete`，封装成：
  - `test(config)`：PROPFIND Depth 0，207/200 成功，401/403 → `WebDavException(status)`；
  - `makeDirs(config, path)`：逐级 MKCOL，405（已存在）视为成功；
  - `list(config, dir)`：PROPFIND Depth 1，XML 用 JDK `DocumentBuilderFactory` 解析（**不用 `android.util.Xml`，JVM 单测可跑**）；
  - `put/get/delete`；delete 404 视为成功、失败只记日志（清旧备份不该整体失败）。
  - href 归一化：去掉 `://host`、去掉 WebDAV 根前缀、去尾 `/`，兼容绝对 URL / 绝对路径 / 相对路径三种服务端实现。
  - XXE 加固的 feature 逐个 `runCatching`：Android 解析器不一定支持 `disallow-doctype-decl`，不支持时不能让「列目录」直接失败（真机验证时踩到过）。
  - 超时 15s / 60s / 60s；日志只记 `webdav.put path=… bytes=…`，不含凭据。
- `data/WebDavBackup.kt`（新增）：
  - `WebDavRetention`：`REMOTE_KEEP = 10`、`LOCAL_KEEP = 3`、`stale(names, keep)` 纯函数（按名字倒序保留，时间戳格式保证字典序 = 时间序）。
  - `backupNow()`：export → `makeDirs` → PUT → `pruneRemote`，日志 `webdav.backup name/bytes/pruned/dir/base`（base 走 `Redact.url`）。
  - `restore(remote)`：**先** `writeLocalSnapshot()`（`filesDir/webdav-snapshots/snapshot-<stamp>.zip`，保留 3 份）→ GET → `BackupRepository.restore(bytes)`；坏包抛 `bad backup file`。快照写失败就不继续，避免「远端也坏了、本地也没有」。
  - 日志 `webdav.restore.begin/done/fail`，done 带 cards / worldBooks / chats / messages / skipped。
- `data/AppContainer.kt`：`webDavBackup` 懒加载，复用 `backupRepository`、`appPrefs`、`secretStore`。
- `ui/backup/WebDavViewModel.kt` + `WebDavScreen.kt`（新增）：`WebDavUiState`（配置草稿 + 远端列表 + busy + message + restoreTarget）；所有网络动作共用 `busy` 串行保护；消息统一走 `UiText`。
- `ui/HomeScreen.kt`：新增 `Routes.WEBDAV = "webdav"`；`ui/profile/ProfileScreen.kt`：第二组设置新增「云备份（WebDAV）」入口（`Icons.Filled.Cloud`）。
- `AndroidManifest.xml`：`android:usesCleartextTraffic="true"`，允许局域网 / 本地 dev server 的 `http://`（公共网络仍建议使用 https）。
- `tools/webdav_dev_server.py`（新增，仅测试）：Python 标准库实现的 PROPFIND / MKCOL / PUT / GET / DELETE + Basic Auth，配合 `adb reverse tcp:8765 tcp:8765` 在本机完成真机闭环。
- 文案：zh / en 各新增 30 条（`profile_webdav*`、`webdav_*`）。
- 单测：`WebDavRetentionTest`（4 例：保留 10、少于上限、空列表、keep=0）、`WebDavClientTest`（7 例：绝对 href 解析 + 跳过自身 + Depth/MKCOL/PUT/GET/DELETE、相对 href、401 分类、207 视为成功、405 视为已存在）。

## 代码检视与修复（0.24.0）

独立检视（`docs/reviews/v024/SUMMARY.md`）报 P0 零条、P1 六条、P2 二十条；本版修完全部 P1 与其中影响正确性/体验的 P2，其余归档到 0.24.x。

| 编号 | 问题 | 修法 |
| --- | --- | --- |
| P1-1 | href 归一化混用编码/解码路径，非 ASCII 基址下列表/恢复/清理全 404，且 DELETE 404 被静默吞掉 | 路径统一用「解码后的段」表达：`percentDecode` 只解 `%XX`（保留 `+`），与 `HttpUrl.pathSegments` 的段前缀比较，拼 URL 时逐段 `addPathSegment` 交给 OkHttp 编码；新增中文基址 + `+` 文件名两条单测 |
| P1-2 | `busy` 未覆盖恢复：备份中可发起恢复、可二次恢复 | `askRestore/confirmRestore` 首行 `if (busy) return`；列表行 `clickable(enabled = !busy)` |
| P1-3 | 会话「先建头、后插消息」非事务：取消/异常后重试被「已存在」跳过，消息永久丢失 | 新增 `ConversationDao.insertExactWithMessages`（`@Transaction`），恢复走它；`runCatchingCooperative` 让 `CancellationException` 穿透而不是被翻成失败 |

## 已知限制

- 不做自动合并：恢复是「补缺」语义（同名角色 / 世界书 / 会话跳过），不会覆盖或更新已有条目；需要「整库替换」时得先手动清库。
- 不做定时备份与后台上传：备份是一次性前台动作，7 MB 级别在局域网上约 1–2 秒，公网视带宽而定。
- 备份不加密：zip 里的内容（含对话）是明文；网盘侧的安全由用户与网盘承担。
- `usesCleartextTraffic=true` 是全局开关（为了局域网 / 自建服务器）：UI 在地址以 `http://` 开头时会红字提示「仅建议局域网使用，公网请改用 https」，但没有协议级拦截；以后要收紧可改成 `networkSecurityConfig`。
- 列表只识别 `backup-*.zip`；用户手工放进目录的其它文件名不会显示。
- 恢复前快照只保留 3 份，放在应用私有目录（`files/webdav-snapshots/`），**App 内没有回滚入口**：它的用途是排障（adb / 文件管理器取出），卸载 App 会一并删除。弹层文案已按此改写。
- `tools/webdav_dev_server.py` 只用于验收，没有并发/大文件/断点续传处理，不要当生产服务用。
