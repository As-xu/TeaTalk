# 26 - 发布准备（0.26.0）

V1 的最后一块：把「能跑」变成「能发」。四条线各自独立，但都属于发布前必须补齐的承诺。

## 目标

1. **后台保活**：切走 App 时正在生成的回复不被打断（路线图风险 #4）。
2. **应用内更新**：能发现新版本、下载、交给系统安装，且校验完整性。
3. **首启知情同意 + 成人内容开关**：首次启动说明数据去向与内容分级；成人内容可关。
4. **真实卡回归 + 发布流程**：20 张真实 SillyTavern 卡片的解析回归，以及一条命令出包。

## 范围取舍

- 保活用 `dataSync` 前台服务 + 无声通知，只在生成期间存在；不常驻、不做后台定时任务。
- 更新只查 GitHub Releases 的 latest（可被 `teatalk.update_feed` 覆盖，仅 debug 生效），不做灰度/渠道包。
- 安装走系统 `ACTION_VIEW` + `FileProvider`，不申请 `REQUEST_INSTALL_PACKAGES` 之外的静默安装能力。
- 成人内容只做「列表隐藏」，不做密码锁：这是客户端本地开关，不是家长控制。
- 20 张真实卡不进仓库（版权 + 体积），回归测试由外部目录驱动，缺目录时整组跳过。

## 交互

| 场景 | 行为 |
| --- | --- |
| 生成中切到后台 | 通知栏出现「茶话 · 正在生成回复」（无声、不含内容），回复继续流式生成 |
| 生成结束/失败/停止 | 通知与前台服务立即撤下 |
| 关于页「检查更新」 | 手动检查总是发起请求（`force=true`）；`UpdateManager` 保留 24h 节流接口给以后的静默检查用；有新版显示版本号与「下载并安装」 |
| 下载中 | 进度条 + 百分比 + 「取消」；取消回到「发现新版本」 |
| 下载完成 | 「继续安装」拉起系统安装器；未授权「安装未知应用」时由系统弹窗引导，App 内当前只给静态说明 |
| 首次启动 | 全屏同意页：三条说明 + 「显示成人内容」开关 + 「同意并继续」/「不同意，退出」 |
| 我的 → 显示成人内容 | 随时可改；关闭后角色列表与会话列表隐藏带 `nsfw` 标签的条目 |

## 实现要点

### 一、前台保活

- `app/src/main/java/com/teatalk/xs/service/GenerationService.kt`：`startForeground(4201, notification)`，channel `generation`（`IMPORTANCE_LOW`，无声无振动），通知标题「正在生成回复」，**不含角色名与聊天内容**；`ACTION_STOP` 停止；`START_NOT_STICKY`。
- `app/src/main/java/com/teatalk/xs/data/GenerationKeepAlive.kt`：引用计数 `begin()/end()`，归零才停服务；`runCatching` 包住启动，通知权限被拒也不影响生成。
- `ChatScreen.kt` 的 `collectStream` 改为 `keepAlive.begin()` + `try { collectEvents(...) } finally { keepAlive.end() }`。
- `MainActivity` API 33+ 请求 `POST_NOTIFICATIONS`；Manifest 增加 `FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_DATA_SYNC`、`POST_NOTIFICATIONS` 与 `<service ... foregroundServiceType="dataSync" />`。

### 二、应用内更新

- `data/update/UpdateClient.kt`：`GET https://api.github.com/repos/As-xu/TeaTalk/releases/latest`；404 → `Result.None`（没有 Release 不算错误）；解析 `tag_name`、`.apk` 资产、`digest:sha256:`、`html_url`；`isNewer()` 按数字段比较。
- `data/update/UpdateInstaller.kt`：下载到 `cacheDir/updates/`，先写 `.part`，循环里检查协程是否有效；sha256 取自 release `digest`，缺失时尝试同名 `.sha256`，两者都没有时至少比对下载长度；取消/失败删除 `.part`；`install()` 用 `FileProvider`（`res/xml/file_paths.xml` 新增 `cache-path updates/`）。
- `data/update/UpdateManager.kt`：状态机 `Idle / Checking / UpToDate / Available / Downloading / Ready / Failed`；24 小时节流（`AppPrefs.lastUpdateCheckAt`）；取消下载直接复位状态，进度回调带 `cancelled` 守卫。
- `AboutScreen` 新增「检查更新」卡片与状态弹层；文案 zh/en 各 12 条。

### 三、知情同意 + 成人内容

- `ui/consent/ConsentScreen.kt`：全屏说明页，`onAccept(nsfw)` 写入 `AppPrefs.consentAccepted` / `nsfwAllowed`。
- `MainActivity` 在 `setContent` 前判断 `consentAccepted`，未同意则只渲染同意页。
- `CharactersViewModel.applyFilters(..., allowNsfw)` 过滤 `nsfw` 标签；`ConversationDao.observeChats` 的 SQL 用 `tagsJson LIKE '%"nsfw"%'`（会话角色或成员角色任一命中）算出 `hasNsfw`，`ChatListViewModel` 在开关关闭时过滤。
- 「我的」页新增「显示成人内容」开关，随时可改。

### 四、真实卡回归与发布

- `app/src/test/java/com/teatalk/xs/data/CardCorpusTest.kt`：读 `-Dteatalk.cards.dir`，逐张 `CardParser.parse`，断言有名字、有可导入内容、无 U+FFFD；目录缺失时 `Assume` 跳过。
- `tools/release.sh`：校验版本号与 `build.gradle.kts` 一致 → `assembleDebug` → 拷到 `dist/TeaTalk-<version>-debug.apk` → 生成 `.sha256`（路径形如 `*TeaTalk/dist/...`，可在 `TeaTalkApp/` 下 `sha256sum -c` 校验）。
- 发布手动步骤：`git tag v<version>`、GitHub Releases 上传 apk 与 sha256、把 `tag_name` 写成 `0.27.0` 形式（不带 `v` 也能解析）。

## 代码检视与修复（0.26.0）

独立检视者（只读、不改文件）复核了更新链路、前台服务、同意门与测试脚本，结论与修复见 `docs/reviews/v026/SUMMARY.md`。本版实际修掉的问题里，值得单独说明的三条：

- **更新源不再可被同机 App 改写**：`teatalk.update_feed` 只在 `-Pteatalk.feedOverride=true` 构建里生效（`BuildConfig.FEED_OVERRIDE`），并把远端文件名限制在 `cache/updates/` 内。
- **成人内容开关覆盖搜索入口**：消息搜索 SQL 与列表用同一套 `nsfw` 判定，不再出现「列表看不到、搜索能搜到」。
- **前台服务用 `stopService` 收尾**：避免 Android 12+ 后台结束生成时因 `startForegroundService` 被拒而留下常驻通知。

发布签名仍是缺口：当前 `dist/` 里是 debug 签名包，安装到别人设备需要先允许未知来源，且升级覆盖正式签名包会失败。正式签名与 CI 出包放到 V1.1。

## 0.26.1：真实卡回归与开场白选择

### 样本与结果

样本不入库（版权 + 体积），放在仓库外的 `D:\Project\TeaTalkApp\cards20\`，用 Gradle 系统属性传进去：

```
MSYS_NO_PATHCONV=1 cmd.exe /c "D:\Project\TeaTalkApp\.tools\gb.bat :app:testDebugUnitTest --tests *CardCorpusTest* -Dteatalk.cards.dir=D:/Project/TeaTalkApp/cards20"
```

本轮目录里实际有 31 张 PNG 卡（另有 4 张 jpg、1 张 gif、1 张 webp 是普通图片，测试按扩展名忽略）：

| 指标 | 结果 |
| --- | --- |
| 解析成功 | 31 / 31 |
| 编码损坏（U+FFFD） | 0 |
| 空壳卡（只有名字/标签，无设定与开场白） | 1（`V1.png`，卡片本身如此，不是解析缺陷） |
| `first_mes` 是模板占位、真开场白在 `alternate_greetings` | 6 |

### 由此发现的问题与修复

模板占位卡（`<音乐>` + `<开场白>`、`<Gameplay_Guide>` 这类）以前会把这个占位符当开场白插进新会话，用户看到的就是两行尖括号。修复：

- 详情页「开始聊天」在**没有历史会话**且卡里有多段开场白时，先弹「选择开场白」；每项显示第一条像正文的行（跳过 `#` 标题、`===` 分隔线、代码围栏），不直接截前 80 字。
- 选中后走 `CharacterRepository.startConversation(characterId, greeting)`，新建会话时用选中的文本插入开场白；已有会话时点「开始聊天」仍旧直接回到最近一条，不弹选择。
- 纯函数 `Greetings`（`options` / `preview` / `needsChoice`）配 6 个单测，覆盖去空、去重、模板占位与截断。

真机（TAS-AN00）验证：导入 5 张卡后列表显示中文名与头像；详情页显示作者、`PNG_V3`、标签、`世界书 · 42 条`；选「开场白 1」后日志 `Chat conversation.start characterId=1 conversationId=1 created=true greetingChars=1334`，聊天气泡显示该段正文；关掉「显示成人内容」后列表 5 张变 4 张，重新打开恢复。

## 已知限制

- 开场白选择只作用于**新建会话**；已有会话不会重播开场白（避免覆盖聊天记录）。
- 空壳卡仍允许导入（名字与头像有效），设置页可编辑补全。
- `alternate_greetings` 很大的卡（最大 170KB）会导致详情页解析稍慢，已放在 IO/Default 线程，未做惰性分段。
- 更新检查只认 GitHub Releases `latest`；仓库没有 Release 时一律显示「已是最新」。
- 安装依赖用户授予「安装未知应用」权限；debug 签名包在正式签名上线前会覆盖安装失败（需先卸载）。
- 下载不支持断点续传，取消后重新下载。
- `dataSync` 前台服务在 Android 14+ 有单次时长上限（系统限制），超长生成仍可能被系统中断。
- 成人内容开关只隐藏列表条目，不加密本地数据；知道包名的人仍可通过文件系统读取。
- 20 张真实卡回归需要本机提供样本目录，仓库内无法自动执行。
- Android 的 ICU 正则比 JVM 严格：`\{\{[^}]*}}` 这类模式在 JVM 单测能过，真机 `Greetings` 初始化即抛 `PatternSyntaxException`。发版前必须在真机上点一次入口，不能只信 JVM 单测。
- 0.26.1 的检视记录见 `docs/reviews/v0261/SUMMARY.md`（P0 无，P1 四条全修，P2 七条已修、两条记录在案）。
