## 发现的问题

- **P1 长文翻译无结果**：开场白这类 2000+ 字文本走 `TranslationRepository.translate` → `TranslationClient.complete(maxTokens = 4096)`，返回可能被截断或超时；`clean()` 后为空则归 `EMPTY_RESULT`，UI 只回到「翻译」且 snackbar 易被忽略。
  建议：①按段落分块翻译并拼接（每块 ≤ 1500 字）；②失败时在章节卡内显示错误行（而非仅 snackbar）；③`maxTokens` 提到 8192。

## 复现要点（设备自动化）

- 截图：`adb exec-out screencap -p` 拉回本地；`screen_capture` 工具在当前版本返回 `embeddedRef` 结构错误，不可用。
- 坐标必须用 `uiautomator dump` 的 bounds 取中心：长按菜单/弹窗列表按估算坐标会点到相邻项。
- `adb shell input text` 不支持中文（`NullPointerException ... get length of null array`），中文内容需手动输入或用 ASCII 验证流程。

## 0.21.2 复测（P1 长文翻译）

> 2026-11-04 22:20 起，设备 `XPLGL21A22000007`（TAS-AN00 / Android 12），APK `TeaTalk/dist/TeaTalk-0.21.2-debug.apk`。

### 问题复现（0.21.1）

- 梁诗月「开场白」约 2168 字，点「翻译」后 `max_tokens=4096` 被截断，`clean()` 得空串，`TranslationClient.extractText` 返回 `""` → `EMPTY_RESULT`，动作退回「翻译」且无译文。
- 截图：`TeaTalk/docs/screenshots/v021/10-card-detail.png`、`11-card-translating.png`、`12-card-translate-failed.png`。

### 修复内容

- 新增 `TranslationChunker`：按空行切段、贪心装箱，单段超限硬切；默认上限 `1500` 字。
- `TranslationClient.complete` 的 `maxTokens` 默认从 `4096` 提到 `8192`。
- `TranslationRepository.translate` 顺序翻译各块并拼接结果，失败时记录块序号；`trans.ok` 日志新增 `chunks`。
- 章节卡内直接显示失败原因（`SectionCard.error` → `TranslationFailure.toUiText()`，`cs.error` 红色小字），不再只靠 snackbar。
- 顺带修 `重新翻译` 未透传 `force`（卡片详情 / 世界书 / 聊天气泡统一 `translate(..., force = force)`），否则会直接命中缓存。
- 新增 `TranslationChunkerTest`（5 例）。

### 复测结果

| 项 | 结果 | 证据 |
| --- | --- | --- |
| 长开场白（2168 字）翻译 | 通过 | `trans.split chunks=2 chars=2168` → 两次 `trans.req.ok`（17098ms/5108 chars、5409ms/1906 chars）→ `trans.ok lang=en chunks=2`；出现「显示原文 / 重新翻译」+ 英文译文卡 |
| 截图 | — | `TeaTalk/docs/screenshots/v021/13-card-translate-fixed.png`、`14-card-translated-long.png` |

## 0.21.3 补验（世界书条目翻译 + 失败内联提示）

> 2026-11-05 00:10 起，设备 `XPLGL21A22000007`（TAS-AN00 / Android 12），APK `TeaTalk/dist/TeaTalk-0.21.3-debug.apk`（versionCode 47）。

### 测试素材

- 自造世界书 `D:/Project/TeaTalkApp/.tools/wb_teahouse.json`（ST 格式，2 条：`茶馆设定` keys=`茶馆, tea house`；`老板娘` keys=`阿箬`），用 `adb push` 落到 `/sdcard/Download/`，应用内「我的 → 世界书 → 导入世界书」经 SAF 选择导入，toast「已导入「wb_teahouse」（2 条）」。

### 发现问题（0.21.2 及以前）

- 世界书详情是 `ModalBottomSheet`，翻译失败时 `SnackbarHost` 被弹层遮住 → 用户点「翻译」后**界面毫无反馈**（`trans.fail kind=UnknownHostException` 仍能出现在 logcat）。
- 同时发现 `TranslationRepository` 把 `IOException`（离线/域名解析失败）归到 `UNKNOWN`，即使有提示也只会显示笼统的「翻译失败」。

### 修复内容

- `WorldBooksViewModel` 增 `entryErrors`（`key = bookId:uid`），`translateEntry` 失败写入、开始/成功/显示原文时清除。
- `WorldBookDetailSheet` 接收 `errors`，条目正文下方用 `cs.error` 小字显示 `TranslationFailure.toUiText()`，与角色卡章节一致。
- `TranslationRepository` 把 `IOException` 与 `HTTP xxx` 统一映射为 `NETWORK`，离线时提示「翻译接口请求失败」而不是「翻译失败」。

### 复测结果

| 项 | 结果 | 证据 |
| --- | --- | --- |
| 世界书条目翻译（在线） | 通过 | `老板娘` 点「翻译」→ 动作变「显示原文 / 编辑」+ 英文译文块（`A Ruo, 32, shopkeeper...`） |
| 失败提示（断网） | 通过 | `svc wifi disable; svc data disable` 后点「翻译」→ 条目下方红字「翻译接口请求失败」，`trans.fail kind=UnknownHostException` 同步出现在日志 |
| 恢复网络后重试 | 通过 | `svc wifi enable; svc data enable` 后同一条目再点「翻译」→ 红字消失、译文出现 |
| 截图 | — | `TeaTalk/docs/screenshots/v021/15-worldbook-entry-translated.png`、`16-worldbook-translate-error.png` |

### 复测注意

- 每次 `adb install` 后「我的」页首屏滚动位置不同，行坐标会漂移 100–150px，必须 `uiautomator dump` 取 bounds 再点。
- 熄屏后再亮屏，App 可能回到上一级页面且内存态译文丢失（`translations` 表缓存仍在，再点一次即命中缓存）。
