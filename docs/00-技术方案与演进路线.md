## 1. 定位：做什么、不做什么

### 1.1 三个痛点 → 三条设计原则

| 你的痛点 | 真正的原因 | TeaTalk 的原则 |
|---|---|---|
| ① 没有原生 App | ST 是"必须跑 Node 服务端的本地 Web 应用"，官方 Android 方案是 Termux 装 Node + 改 config.yaml | **P1 零运维**：装完就能聊；不装 Node、不填 YAML、不开电脑 |
| ② 功能冗余 | ST 是「聊天前端 + 提示词工程台 + 扩展宿主」三合一，约 70% 界面复杂度服务于后两者 | **P2 克制**：3 Tab、≤40 项设置、固定提示词管线；新功能默认关闭 |
| ③ 界面不好看 | 本质不是配色，是**桌面交互假设**（hover 展开、右键菜单、9 个顶栏抽屉、108 处弹窗） | **P3 移动优先**：长按 ActionSheet、底部 Sheet、大标题、单列信息流 |

### 1.2 目标 / 非目标

**目标（v1.0）**
- 老 ST 用户能把 `characters/*.png`、`worlds/*.json`、`chats/*.jsonl` 三件套**无损搬过来**，继续同样的对话。
- 新用户从安装到发出第一条消息 ≤ 4 步、≤ 2 分钟、不需要读文档。
- 同一张卡、同一套世界书、同一个预设下，模型的**输入上下文与 ST 基本一致**（可对拍验证）。
- 长回复不被系统杀后台；弱网能重试；API Key 不落地明文。

**非目标（v1 明确不做）**
- 提示词工程台（Prompt Manager 树、Context Template、Instruct Mode、CFG、logprobs、tokenizer 面板）。
- 扩展宿主（不加载 ST 的 JS 扩展，不兼容其 manifest）。
- 41 个模型接入源（只留 5 个预设 + 自定义 Base URL 逃生口）。
- 文本补全（Text Completion）后端、NovelAI、Horde、STscript 与 297 个斜杠命令。
- 本地模型推理、图片生成、TTS、向量记忆/RAG、云同步、多用户与 Web 版。
- iOS（但 `:core` 保持纯 Kotlin，未来可走 KMP）。

### 1.3 市场位置（为什么还值得做）

检索到的先行者分三类（未逐一验证质量与活跃度）：

| 路线 | 代表 | 它解决了什么 | 它没解决什么 |
|---|---|---|---|
| 套壳（本地 Node + WebView） | [SillyTavernAndroid](https://github.com/doomedskull1011/SillyTavernAndroid) | "手机上能跑 ST" | 仍是桌面 Web UI；耗电、包体大、启动慢；本质没变 |
| 原生重写 | [NativeTavern](https://github.com/miaoxworld/NativeTavern)、[rikkahub 的 ST 分支](https://github.com/MiaoWuNYA/rikkahub-sillytavern-android) | 证明"原生重写"技术可行 | 普遍走"功能堆叠"路线（缓存、群聊、插件、QQbot…），仍在和 ST 比"多"；UI 打磨不足 |
| 网页移动化 | [RisuAI](https://github.com/kwaroran/RisuAI) / PocketRisu | 移动浏览器体验比 ST 好 | 不是原生；无法直连厂商 API；无本地能力 |

**空档**：所有人都还在"功能竞赛"，没人把"**少而精**"当卖点。你的痛点 ② 恰恰是市场空白，而不是劣势。
TeaTalk 的对外话术应是「**比 ST 简单，但该有的都有**」，而不是「和 ST 一样全」。

## 2. 关键决策（ADR 摘要）

> 这 6 条决定了后面所有工程细节。它们现在改成本很低，M2 之后改成本极高。

### D1｜原生重写 UI，不做套壳 —— 采纳

- **否掉的方案**：本地 Node + WebView（Termux/nodejs-mobile）。理由：痛点 ③ 是 UI，套壳一行 UI 都改不了；nodejs-mobile 已长期无维护；包体 +50~100MB、冷启动 +3~5s、后台耗电不可控。
- **代价**：ST 的 14.6 万行前端不能复用，UI 全部重写。但这正是价值所在。

### D2｜干掉服务端，App 直连模型 API —— 采纳

ST 的服务端只干三件事：**绕 CORS**、**保管密钥**、**代理 41 家厂商**。Android 原生：
- 无 CORS 限制 → 直接 `OkHttp` 调 `https://api.xxx.com/v1/chat/completions`；
- 密钥放 Android Keystore（`EncryptedSharedPreferences`/`Keystore` 派生密钥 + SQLCipher 可选）；
- 厂商收敛到 3 类协议（OpenAI 兼容 / Anthropic / Gemini），覆盖 95% 用户。
- 收益：启动快、省电、离线可读历史、无端口无局域网。
- **保留后门**：`ConnectionProfile` 支持自定义 Base URL + 自定义 Header，覆盖国内"中转站"；V2 再加「连接 PC 上的 ST」适配器（调研见 `02` §8，鉴权是 cookie session + CSRF，可行但脏）。

### D3｜固定生成管线，不做 Prompt Manager 树 —— 采纳

- ST 的 `PromptManager` 允许用户拖拽任意提示词块、改顺序、改注入深度——这是"提示词工程台"的核心，也是 80% 用户永远不碰的部分。
- TeaTalk 用**一条固定顺序的管线**（§4.2），把"风格切换"收敛为「预设 = 一组开关 + 参数」（是否包含示例对话、作者注、世界书预算等）。
- 代价：极客用户会觉得不够自由。**这是有意的取舍**，V2 再考虑"高级模式"。

### D4｜三级兼容策略 —— 采纳

| 级别 | 内容 | 是否做 | 验收方式 |
|---|---|---|---|
| L1 数据级 | 角色卡/世界书/聊天/预设的导入导出 | **必做** | 导入后字段零丢失；导出能被 ST 再导入 |
| L2 逻辑级 | 同卡同预设同历史下，发往模型的 messages 与 ST 一致 | **必做** | 对拍测试：捕获 ST 真实请求体做 golden case |
| L3 运行时级 | 加载 ST 的 JS 扩展 | **不做** | — |

### D5｜`:core` 纯 Kotlin，与 Android 解耦 —— 采纳

引擎（卡片解析、世界书扫描、提示词组装、宏、token 预算、Provider 协议）全部放 `:core`，不依赖 `android.*`。
收益：JVM 单测跑得快；对拍测试不需要模拟器；未来 iOS/桌面可复用；强迫引擎无隐藏状态。

### D6｜许可证 AGPL-3.0（待你确认）

- ST 本体 AGPL-3.0。我们即使只"照着行为重写"，格式规范、算法描述、文案仍受其影响；直接抄任何 JS 片段则**必然**是衍生作品。
- 建议：TeaTalk 直接 AGPL-3.0 开源。对这类"要填 API Key、要存私密角色卡"的应用，**可审计**本身就是卖点。
- 若你想闭源/商业化：必须 clean-room（只读规范不读实现）、不复制 UI 文案与图标，并接受"法律上仍需个案评估"。

## 3. 产品形态

### 3.1 信息架构（3 Tab）

```
启动
├─ 有历史会话 → 直接进「聊天」Tab（上次会话置顶）
└─ 无历史 → 3 屏引导（选模型 → 导第一张卡 → 认识 3 个动作）

底部 Tab
├─ 聊天   会话列表：头像 + 名字 + 最后一句 + 时间 + 未读点
│         长按 → 重命名/导出/删除（可撤销）
├─ 角色   3 列网格 + 搜索 + 收藏筛选；"+" → 导入；点卡片 = 开聊
│         "⋯" → 详情/编辑/绑定世界书/导出
└─ 我的   模型（当前模型 + 参数）· 人设 · 世界书 · 外观 · 数据 · 关于
```

设置页只有**一层分组列表**（≤40 项）：常用的露在外面，"高级"折叠。

### 3.2 关键旅程（目标：4 步开聊）

1. 首启 → 选模型（5 张卡片：OpenAI / DeepSeek / Claude / Gemini / 自定义）→ 粘 Key → 「测试连接」出绿灯。
2. 「导入角色卡」→ 系统文件选择器（或从微信/QQ 直接"用 TeaTalk 打开"）→ 自动解析出名字与头像 → 完成。
3. 进入聊天 → 自动生成开场白（`first_mes` 或 `alternate_greetings` 作为可切换首条）。
4. 发消息 → 流式回复。**没有任何一步需要"保存设置"**。

### 3.3 视觉与交互（对齐"QQ/微信"）

- **信息密度**：单列、左头像右文字、时间分组；不做多栏、不做悬浮窗。
- **气泡**：角色消息左对齐、浅底、可满宽（长文易读）；用户消息右对齐、品牌色。**不做微信式完全对称**——角色扮演文本长，对称气泡会窄得难读。
- **组件**：Material 3 Expressive；统一 3 种弹层（Dialog / BottomSheet / Snackbar），禁止自造第 4 种。
- **手势白名单**（每个手势必须有等价按钮）：返回、下拉刷新、上滑加载更早、长按消息、左右滑切换消息版本。
- **动效**：只保留 3 类（列表进出、Sheet 升降、消息出现），其余不加。
- **深色**：跟随系统 + 手动三态；字体大小三档；可选纯色/图片聊天背景。

## 4. 技术架构

### 4.1 分层

```
┌──────────────────────────────────────────────────────┐
│ :app  · Jetpack Compose (M3)                          │
│   ChatList / Chat / CharacterGrid / WorldBook /       │
│   Settings / Onboarding + Navigation + ViewModel      │
├──────────────────────────────────────────────────────┤
│ data  · Room(角色/聊天/消息/世界书/预设/连接)          │
│       · DataStore(设置) · SAF 导入导出 · 备份 zip      │
├──────────────────────────────────────────────────────┤
│ :core · 纯 Kotlin，无 android.*                        │
│   card    PNG tEXt / charx / JSON 解析                 │
│   lore    世界书扫描 + 激活                            │
│   prompt  固定管线组装                                 │
│   macro   {{char}}/{{user}}/变量/随机                  │
│   render  正则 hooks（V1）                             │
│   token   jtokkit + 启发式估算                         │
│   net     OkHttp + SSE（OpenAI/Anthropic/Gemini）      │
└──────────────────────────────────────────────────────┘
```

依赖方向单向：`app → data → core`。`:core` 不反向依赖 Android。

### 4.2 生成管线（只复刻 ST 的 Chat Completion 分支）

> 逐函数规格见 `docs/research/01-generation-pipeline.md`；本节是骨架与硬约束。

**边界（重要）**：只实现 ST 的 **Chat Completion 路径**。Text Completion 路径整条不做 —— 因为不需要 Handlebars/story string（context template）、instruct mode、文本补全后端。**这是 L2 逻辑兼容能达成的最大前提。**

```
点击发送
 ① 装载上下文     角色卡 raw_json + 人设 + 历史 + 世界书集合
 ② 世界书扫描     ST 是独立一次扫描，先于提示词组装：
                  · 倒序 chat + scanDepth(默认 2) + 主键任一 / 次键四逻辑
                  · constant / sticky / cooldown / delay / 概率 / 包含组
                  · 预算默认 25%，首次溢出即放弃后续条目
                  · 产出 8 类：worldInfoBefore/After、ANTop/ANBottom、
                    EMTop/EMBottom、atDepth、outlet（供宏取用）
 ③ 组装消息       **不是拼字符串**，而是按 prompt_order 填稀疏槽位：
                  main → worldInfoBefore → personaDescription → charDescription
                  → charPersonality → scenario → enhanceDefinitions → nsfw
                  → worldInfoAfter → dialogueExamples → chatHistory → jailbreak
                  （控制提示词永远最后；atDepth 注入在 splice 后整体 reverse）
 ④ 宏替换         固定三段 preEnv → env → postEnv；发送前多轮替换、显示时再替换一次
 ⑤ 渲染 hooks     正则清洗（V1 开，接口 MVP 就留）
 ⑥ Token 预算     预算 = context − max_tokens；每加一条立刻扣；
                  历史从**最新往最旧**加，**加不下即 break**（不重排、不摘要）
                  计数：OpenAI 系 jtokkit 精确；其他启发式 + 预留 10%
 ⑦ 请求 + 流式    messages 与采样参数分离 → SSE → 增量落库 → 停止串截断
                  → reasoning 提取 → 写入新版本（swipe）
```

**必须逐字复刻的 4 件事**（其余可放宽）：

1. 默认提示词文本 + 默认 `prompt_order`（少一条或错位 → 角色 OOC）
2. 世界书匹配语义（主/次键、正则键、大小写、整词）
3. Token 预算算法（减法 + 加不下 break → 决定长聊截断点）
4. 宏替换顺序（preEnv → env → postEnv → `{{original}}`/`{{lastMessage}}` 才不错值）

**明确简化**：向量记忆、`tool_calls`、多模态内联、reasoning 签名回传、群聊 nudge、递归扫描（默认关）、包含组权重（仅多条目互斥场景）。

**状态机**：`idle → generating → stopping → idle`。生成中禁用会改变上下文的操作（删除/编辑更早消息），其他操作排队。

### 4.3 数据模型（Room，MVP 建表即含预留字段）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `character` | id, name, avatar_path, spec, spec_version, **raw_json**, worldbook_id, fav, tags, created_at, updated_at, source | `raw_json` 存原始卡片全文，保证零丢失与回写 |
| `worldbook` | id, name, **raw_json**, 全局启用标记 | 条目全 16 字段存 JSON，UI 只露 3 个 |
| `chat` | id, character_id, title, **participants**, created_at, updated_at, metadata_json | `participants` 为群聊预留 |
| `message` | id, chat_id, seq, speaker_id, role, name, content, reasoning, send_date, **parent_id**, **version_group_id**, **version_index**, media_json, extra_json | 分支/多版本**现在入库**，UI 后做 |
| `connection` | id, name, type, base_url, model, params_json | 多 Profile 预留；密钥单独存 Keystore |
| `persona` | id, name, description, avatar_path, lorebook_id | |
| `preset` | id, type, name, payload_json | 导入 ST 预设用 |

### 4.4 模型接入层

| 协议 | 端点 | 说明 |
|---|---|---|
| OpenAI 兼容 | `POST {base}/chat/completions`、`GET {base}/models` | 覆盖 OpenAI / DeepSeek / Moonshot / 智谱 / SiliconFlow / OpenRouter / LM Studio / Ollama / 各类中转 |
| Anthropic | `POST /v1/messages`（`x-api-key` + `anthropic-version`） | system 是顶层参数；SSE event 类型化；支持 `cache_control` 省钱 |
| Gemini | `POST /v1beta/models/{model}:streamGenerateContent?alt=sse` | `systemInstruction` + `contents[].parts`；`safetySettings` |

统一抽象：`ChatMessage(role, parts[], name?)` → `StreamEvent(delta | usage | finish)`。
要点：默认发送 `stream:true`；停止串在客户端截断；`reasoning_content`/`thinking` 单独字段渲染为可折叠"思考"块；错误映射成人话（"Key 无效 / 余额不足 / 该地区不可用 / 换 Base URL"）。

### 4.5 渲染层

- Markdown：粗体/斜体/引用/列表/代码块/表格；代码块等宽字体 + 复制。
- 流式：按 token 增量刷新，300ms 节流；未闭合代码块不闪烁（先渲染为纯文本，闭合后升级）。
- 多版本：同一条 AI 消息保留 `swipes`，左右滑或按钮切换；"重新生成"= 新建版本而非覆盖。
- 长会话：`LazyColumn` + keyset 分页（每次 50 条）；滚动到顶加载更早。

### 4.6 兼容性细节（来自 `docs/research/02`）

- 角色卡：PNG 的 `tEXt` chunk，`chara`(V2) / `ccv3`(V3)，值为 **base64 后的 JSON**；`ccv3` 优先；校验**宽松**（真实卡经常缺字段）。
- 世界书：`{entries: {"<uid>": {...}}}`，**对象不是数组**；`enabled`(CCv2) 与 `disable`(ST) 语义相反；`role` 在世界书里是**数字**、在 `depth_prompt` 里是**字符串**。
- 聊天：`chats/<avatar>/<name>.jsonl`，**每行一个 JSON，第 0 行是 header**（`chat_metadata`），不是消息数组。
- 分支：`swipe`（同条多版本）+ `checkpoint`（整份 jsonl 复制，header 里 `main_chat` 指父）。
- 导入风险：`post_history_instructions`、`extensions.depth_prompt`、`extensions.world`、`chat_metadata.integrity`、预设的 `prompts`/`prompt_order` —— 丢了**不报错但角色行为全变**。
- 主键：avatar 文件名是 ST 的唯一主键（聊天/checkpoint 目录都挂在它上面），但常与卡内 `name` 不一致 → TeaTalk 内部用稳定 id，只在导入期做映射。
- **兼容验收（M0 收尾硬指标）**：准备 **20 张真实角色卡**（V2 / V3 / 纯 JSON / CHARX / 缺字段的「脏卡」各若干）→ 全部导入零丢失、导出后 ST 能原样读回；世界书与聊天记录各抽样 5 份同样验证。

## 5. 技术选型

| 层 | 选型 | 理由 / 替代 |
|---|---|---|
| 语言 | Kotlin 2.x | 官方主推；`:core` 可 JVM 单测 |
| UI | Jetpack Compose + Material 3 Expressive | 声明式、动效成本低；XML 不返工 |
| 导航 | Navigation Compose（type-safe routes） | 单一 Activity |
| 架构 | MVVM + UDF（StateFlow）+ Repository | 团队门槛最低 |
| DI | Hilt | 编译期校验；Koin 更轻但反射期错误 |
| 本地库 | Room + KSP | 迁移可控、Flow 支持；SQLDelight 可跨平台但生态弱 |
| 设置 | DataStore(Proto) | 类型安全、无 ANR |
| 网络 | OkHttp 5 + kotlinx.serialization | SSE 手写解析最可控；Retrofit 可选 |
| 图片 | Coil 3 | 头像/背景/异步 |
| 分页 | Paging 3 | 长会话 |
| Token | jtokkit（JVM） | OpenAI 系精确；其他启发式 |
| Markdown | Compose Markdown 渲染器（自研或 OSS） | 需要支持流式半成品 |
| 测试 | JUnit5 + Turbine + Roborazzi | 引擎单测 + 截图回归 |
| 构建 | Gradle KTS + Version Catalog | 依赖集中管理 |
| CI | GitHub Actions（assembleDebug + unit test） | 免费额度足够 |
| 最低版本 | ✅ **minSdk 28**（Android 9）/ compile & target **34** | 2026-10-24 拍板；本机 SDK 仅装 platform 34 与 36.1，先用 34 打通链路，后续再升 36 |

**版本策略**：具体版本号以 Android Studio 2026.1.1 向导生成的 AGP/Kotlin/Compose BOM 为准，本项目不手写猜测版本；升级由 Renovate/Dependabot 提 PR。

**测试策略（关键）**
1. **引擎单测**：卡片解析、世界书扫描、宏、token 裁剪的纯函数用例。
2. **对拍测试（护栏）**：让真实 ST 把请求体发到一个本地"录像机"（把 OpenAI Base URL 指向 `http://127.0.0.1:xxxx`），录下 `messages` 数组作为 golden；TeaTalk 用同卡同预设同历史生成，逐字段 diff。**这是 L2 兼容的唯一可信验收方式。**
   - 前置：本机 Node 可用但 `npm` 已损坏（见附录），`SillyTavern/node_modules` 不存在 —— M0 需先修复并 `npm install` 一次。
3. **UI 冒烟**：Compose UI test 覆盖 3 条主旅程。
4. **真机**：Android 8 / 12 / 15 各一台 + 一台折叠屏。

## 8. 风险登记

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| 1 | 管线复刻偏差（顺序/宏/世界书深度） | 角色"变味"，老用户立刻察觉 | 对拍测试作为 CI 门禁；先复刻高频路径，低频字段先存不用 |
| 2 | ST 版本漂移（1.19 → 1.20+） | 兼容性持续下降 | 锁定兼容基线 1.19.0；数据格式以社区 CCv2/V3 规范为准而非 ST 实现 |
| 3 | Token 计数不准 | 超上下文被厂商拒 / 白花钱 | OpenAI 系用 jtokkit；其他用保守估算 + 预留 10% 余量；UI 标注"估算" |
| 4 | Android 后台杀流式 | 长回复中断 | 生成中用前台服务 + 通知；支持断点续写 |
| 5 | 内容合规 / 商店审核 | 无法上架应用商店 | 先 GitHub APK 分发；商店策略单独评估（NSFW 卡大量存在） |
| 6 | 法律 / 许可证 | 被迫开源或下架 | 定 AGPL-3.0；不抄代码、不抄文案；保留 NOTICE |
| 7 | 范围蔓延 | 做成第二个 ST | MVP 10 项锁死；新需求一律进 Backlog，不进当前迭代 |
| 8 | 厂商风控/地域限制 | 用户"配了也用不了" | 默认推荐 DeepSeek/OpenRouter/中转；错误信息给可操作指引 |
| 9 | 大世界书性能（数千条目） | 发送前卡顿 | 预编译关键词索引；扫描在 IO 线程；命中结果缓存 |
| 10 | 内容 / 托管 | NSFW 内容 + GitHub 托管被投诉 | 仓库与发行页不含成人素材；首次启动知情同意；被下架则迁 Gitee / 自建镜像，签名与更新检查解耦域名 |

## 9. 决策记录（2026-10-24 已锁定）

| # | 决策点 | 结论 | 影响 / 约束 |
|---|---|---|---|
| D1 | 主形态 | **App 直连大模型 API**；不做「连 PC 上的 ST」；Prompt 引擎留在 App 内 | 删掉服务端与 CORS 依赖；用户不用装 Node |
| D2 | 开源与许可 | **社区开源，AGPL-3.0**；不抄 ST 代码与文案，保留 NOTICE | 与 ST 同源、社区信任成本低；日后若想闭源须重授权所有贡献 |
| D3 | 分发 | **自主分发**：GitHub Releases + 应用内更新检查；**不上架任何商店** | 免商店审核；无商店信任背书，需自建下载页与签名校验 |
| D4 | 内容政策 | **允许 NSFW**：首次启动知情同意 + 设置内开关 | 需隐私屏/锁、默认关闭通知预览；成品不投递商店 |
| D5 | MVP 范围 | **Standard**：§7 的 10 项、约 46 人日；不扩张 | 6~8 周可发布；新增需求一律进 Backlog |
| D6 | 平台 | **Android only**；不做鸿蒙 / iOS / 平板专项 | 单端专注；`:core` 保持纯 Kotlin，为未来留口 |
| D7 | 工程标识 | minSdk **28**、包名 **`com.teatalk.xs`**、应用名 **TeaTalk**；compile/target 34（本机 SDK 仅 platform 34 与 36.1） | 与 §5 选型一致；升 36 需另装平台 |
| D8 | 兼容等级 | **ST 角色卡兼容为硬验收**：L1 数据无损 + L2 管线对拍；L3 运行时 JS 插件不做 | M0 收尾用 20 张真实卡做导入零丢失 |
