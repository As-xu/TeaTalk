# 19 · 翻译（0.21.0）

## 目标

让中文用户读英文卡、让英文用户读中文卡：**把「给人看」的文本翻成母语，并且自己说的话也能先翻再发**。

范围内：

- 入站：AI 回复气泡的译文（手动 / 自动）。
- 出站：输入框内容 → 译文预览（可改）→ 用译文发送。
- 独立的「翻译接口」配置：可以和聊天用不同的 provider / model（便宜小模型专门翻）。
- 本地缓存：同一段原文 + 同一目标语言只翻一次。

范围外（留给 0.21.1）：角色卡字段（description / first_mes / 世界书条目）的翻译。

## 设计取舍

| 决定 | 原因 |
| --- | --- |
| 只翻「气泡正文」，不动 system prompt / 世界书注入 / 正则与宏 | 这些是给模型看的指令，翻了会改变行为 |
| 译文与原文分开存（`messages.content` 永不被改写） | 原文是唯一真相；关掉翻译、换语言都能回退 |
| 缓存键 = 目标语言 + 原文（不含 provider/model） | 换模型不该让旧译文失效；要重翻走 `force` |
| 非流式翻译（`stream=false`） | 译文短、要整体替换；流式只会增加复杂度 |
| 出站译文先给用户看、可改，再发 | 机翻可能坏语气，用户要能救 |

## 数据层

- `data/db/Translations.kt`：`translations(hash PK, targetLang, text, engine, createdAt)` + `TranslationDao{ find / upsert / count / clear }`。
- `TeaTalkDatabase` v14 + `MIGRATION_13_14`（建表语句不写 `DEFAULT`，Room 校验索引/默认值才不会崩 —— 0.18.1 的教训）。
- `data/Translation.kt`：
  - `TranslationTarget(code, promptName, label)`，`ALL` = zh-Hans / zh-Hant / en，`of(code)` 未知回退简体。
  - `TranslationKey.hash(targetLang, text)` = SHA-256(`targetLang + "\0" + text`)。
  - `TranslationPrompt.system(target)`：明确要求保留换行、`*动作*`、`{{user}}/{{char}}`、引号与 emoji，不解释不加引号。
- `data/net/TranslationClient.kt`：POST `{baseUrl}/chat/completions`，`stream=false`；`extractText` 兼容 `content` 为字符串或数组片段；`clean` 去掉 ``` 代码块与成对包裹引号；坏响应返回空串，由仓库层归类为 `EMPTY_RESULT`。
- `data/TranslationRepository.kt`：缓存优先 → 解析 provider（`resolve(prefs.translationProviderId)`，空则跟随当前聊天接口）→ 写缓存；失败枚举 `EMPTY_TEXT / NO_PROVIDER / NO_KEY / NO_MODEL / NETWORK / EMPTY_RESULT / UNKNOWN`。

## UI

- **我的 → 翻译**（`ui/translate/TranslationScreen.kt`）：目标语言、自动翻译开关、翻译接口（含「跟随聊天接口」）、缓存条数与一键清空。
- **聊天气泡**：长按菜单多出「翻译 / 重新翻译」与「显示原文」；译文以次级卡片挂在气泡下方，不覆盖原文。
- **输入条**：`/` 与 `+` 之间新增「译」；点击后调用翻译接口，弹出可编辑译文对话框，确认后把译文放进输入框并直接发送。

## 验证

- 单测：`TranslationKeyTest`（键稳定性/隔离/回退）、`TranslationPromptTest`（目标语言、保留标记）、`TranslationClientTest`（content 字符串/数组、代码块、包裹引号、多行、坏 JSON → 空串）。
- 真机：翻译接口配置 → 气泡翻译与「显示原文」→ 自动翻译新回复 → 出站「译」+ 改译文发送 → 二次翻译命中缓存（不产生网络请求）。
