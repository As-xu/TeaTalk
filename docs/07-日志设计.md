# 日志与诊断设计

> 状态：**现状＝没有日志模块**（全仓库 0 处 `android.util.Log` / `println` / Timber）。排查问题只能靠 `adb logcat` 看系统输出和崩溃栈。
> 本文是建议方案，实现排在 M1 第 0 步（约 0.5 人日）。

## 1. 为什么现在要补

| 现状 | 后果 |
| --- | --- |
| 无业务日志 | 导入失败、SSE 断流、Room 异常都只能看到笼统 UI 提示，定位要重跑 |
| 无请求日志 | M1 接模型后，「401 还是 429 / 哪个 URL / 耗时多少」无法回答 |
| 敏感数据无约束 | 一旦随手打日志，角色卡正文、API Key 很容易进 logcat |

## 2. 设计原则

1. **门面统一**：业务代码只依赖 `:core` 的 `TeaTalkLog`，不直接 `import android.util.Log`（`:core` 是纯 JVM 模块，不能依赖 Android）。
2. **分级 + 标签**：`V/D/I/W/E`；标签命名 `TT/<domain>`（`Net`、`Prompt`、`Card`、`Db`、`Ui`、`Chat`）。
3. **结构化**：`TeaTalkLog.i("Net", "chat.request", "model" to model, "messages" to n, "stream" to true)`，不拼长字符串。
4. **默认安全**：release 只输出 W/E 且只到 logcat；debug 额外写文件环形缓冲。
5. **可导出**：设置 → 关于 → 「导出诊断日志」生成本地 txt 分享（用户主动操作）。

## 3. 结构

```
:core/src/main/kotlin/com/teatalk/core/log/
  TeaTalkLog.kt        object 门面：level 阈值 + 多个 LogSink
  LogSink.kt           interface { fun write(level, tag, event, fields, throwable?) }
  RingBufferSink.kt    内存环形 2000 条（随时「查看最近日志」）
  NoopSink.kt

:app/.../log/
  AndroidLogSink.kt    → android.util.Log（release/debug 都挂）
  FileLogSink.kt       → filesDir/logs/teatalk-yyyyMMdd.log（debug，单文件 2MB，保留 3 天）
  HttpLoggingInterceptor（OkHttp）→ 只记 method/URL host/path/status/耗时/SSE 事件数
```

## 4. 事件约定（M1 需要的最小集）

| domain | 事件 | 字段（脱敏后） |
| --- | --- | --- |
| `Card` | `import.start` / `import.ok` / `import.fail` | fileName、source（PNG/JSON/CHARX）、bytes、warnings 数、错误码 |
| `Db` | `db.open` / `db.migrate` | version、耗时 |
| `Net` | `req.start` / `req.done` / `req.error` | host+path（不含 query）、status、ms、stream 事件数、错误类型 |
| `Chat` | `send.start` / `send.first_token` / `send.done` / `send.cancel` | providerId、model、messages 条数、输出字符数、首字延迟、总耗时 |
| `Prompt` | `prompt.build` | 字符数、预算、世界书命中条数 |

## 5. 脱敏规则（硬约束）

- **永不记录**：API Key、Authorization 头、角色卡 `description/first_mes` 等正文、聊天消息原文
- 需要定位时记 **长度 + 前 8 位 SHA-256**（如 `descHash=ab12cd34,len=12043`）
- URL 只记 `scheme://host/path`，丢弃 query 与 fragment
- 异常只记 `throwable.toString()` + 栈首 5 行；`Exception.message` 可能含 URL，先过同一套脱敏

## 6. 开关与查看

- 设置 → 关于：`调试日志`（debug 默认开、release 默认关）、`导出诊断日志`、`查看最近日志`（RingBuffer）
- 诊断导出文件包含：App 版本、设备型号/API、DB 版本、最近 2000 条日志 —— 用户可自检后分享

## 7. 验收

- M1 联调后能仅凭导出日志回答：用了哪个 provider/model、请求耗时、SSE 是否断流、错误归属（401/429/超时）
- `adb logcat | grep -i "sk-"` 与导出日志全文搜索 key 均为 0 命中
- 关闭日志开关后，debug 文件 sink 停止写入且旧文件在 3 天后清理
