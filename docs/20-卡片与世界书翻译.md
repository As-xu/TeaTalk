# 20 · 卡片字段与世界书条目翻译（0.21.1）

目标：把 0.21.0 的翻译能力从「聊天消息」扩到「角色卡字段」与「世界书条目」，
让用户在导入外文卡后能先读懂设定再决定聊不聊，而不必先把卡改成中文。

## 设计取舍

| 选项 | 做法 | 原因 |
| --- | --- | --- |
| 译文存放 | 只放内存（`StateFlow<Map<key, text>>`），不写进角色卡/世界书 | 卡片 JSON 是世界书/正则/导出链路的共同输入，塞译文会污染导出的卡 |
| 持久化 | 只走 0.21.0 的 `translations` 缓存表（键 = 目标语言 + 原文） | 关闭页面再进来能秒回；换模型不会让旧译文失效；强刷走 `force` |
| 触发方式 | 每个段落/条目一个「翻译」按钮，不做「一键全翻」 | 长卡一次全翻会连打多次请求，也容易被限流；按需翻更可控 |
| 展示 | 原文保留，译文以次级卡片追加在下方 | 用户能对照原文；「显示原文」= 收起译文，不是替换 |
| 范围 | 卡片：设定 / 开场白 / 人设与场景（合为一段）/ 创作者注释；世界书：条目正文 | 只翻给人看的正文，不动 `system_prompt`、世界书触发键与正则变量 |

## 复用

- `TranslationRepository.translate(text, targetLang, force)`：目标语言、独立接口、缓存、失败分类全部沿用 0.21.0。
- `TranslationFailure.toUiText()`（`data/TranslationUi.kt`）：把 `NO_PROVIDER / NO_KEY / NO_MODEL / EMPTY_RESULT / NETWORK / EMPTY_TEXT / UNKNOWN`
  统一映射到既有 `translate_*` 文案，卡片页与世界书页共用一份。

## 角色卡详情

- `CharacterDetailViewModel` 新增注入 `TranslationRepository`，并持有：
  - `translations: StateFlow<Map<String, String>>`，key 见 `DetailTranslationKeys`（`desc` / `first` / `details` / `notes`）；
  - `translating: StateFlow<Set<String>>`、`translateMessage: StateFlow<UiText?>`；
  - `translateField(key, text, force = false)`：空文本/已翻译/正在翻直接返回；成功写入 map，失败弹 snackbar；
  - `showOriginal(key)`：从 map 移除该 key，回到原文。
- UI：`SectionCard` 扩了 `translated / translating / onTranslate / onShowOriginal` 四参。
  未翻译时段落下方一行「翻译」（翻译中显示「翻译中…」）；有译文时该行变为「显示原文 … 重新翻译」，
  译文用 `surfaceContainerHighest` 圆角卡片追加。
- 「人设 / 场景」两行合并成一段文本送翻，避免一个请求翻两行导致换行错位。

## 世界书条目

- `WorldBooksViewModel` 新增注入 `TranslationRepository`：
  - `entryTranslations: StateFlow<Map<String, String>>`，key = `"$bookId:$uid"`；
  - `entryTranslating: StateFlow<Set<String>>`、`translateMessage: StateFlow<UiText?>`；
  - `translateEntry(bookId, entry, force = false)` / `showOriginalEntry(bookId, entry)`。
- UI：条目行标题右侧在「编辑」之前多一个动作 —— 「翻译」/「翻译中…」/「显示原文」；
  条目正文有译文时显示译文卡片，否则仍是原来 3 行省略预览。

## 失败与空态

- 未配置翻译接口/Key/模型、网络失败、返回空文本：snackbar 报对应中文文案，不改变页面上的任何状态；
- 卡片按钮在翻译中禁用重复点击（`translating` 集合判重），世界书条目同理；
- 目标语言切换后，同一文本会按新语言重新请求（缓存键含语言），旧语言的译法不会串。
