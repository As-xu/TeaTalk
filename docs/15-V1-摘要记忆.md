# 15 - V1 摘要记忆（Memory Digest）

## 目标

聊天 prompt 只带最近 `HISTORY_LIMIT = 20` 条消息（`ChatEngine.kt`），再往前的内容模型完全不知道：
长会话里用户说「还记得刚才那个茶馆吗」，模型会答非所问。

摘要记忆要补的就是这个洞：**用一段确定性的摘要告诉模型「窗口之外发生过什么」**，
而不是把整段历史塞进 prompt（token 会爆）或额外调一次模型做总结（多一次费用与延迟、
结果不可复现、单测没法断言）。

## 实现

### 抽取：`data/MemoryDigest.kt`（纯函数）

```kotlin
object MemoryDigest {
    const val MAX_LINES = 10          // 最多抽 10 条
    const val MAX_LINE_CHARS = 140    // 单条最多 140 字
    const val MAX_TOTAL_CHARS = 1200  // 整段上限
    const val HEADER = "[Earlier conversation]"
    fun build(older: List<Pair<String, String>>): String?
}
```

- 输入顺序为「旧 → 新」，先过滤空白消息；
- `step = ceil(size / MAX_LINES)`，**从最新往回跳着抽样**，保证越近的事越可能被保留，抽完再 reverse 成时间顺序；
- 每条压成一行（换行 → 空格），超 140 字截断加 `…`；
- 前缀 `- User:` / `- Assistant:` / `- Note:`，超 `MAX_TOTAL_CHARS` 直接停止追加；
- 没有可用内容返回 `null`（调用方不注入空段）。

### 取数：`ChatEngine`

```kotlin
val history = characters.recentMessages(conversationId, HISTORY_LIMIT)…
val memoryDigest = withContext(Dispatchers.IO) {
    val oldest = history.firstOrNull()
    if (oldest == null) null
    else {
        val older = characters.messagesBefore(
            conversationId, oldest.createdAt, oldest.id, MEMORY_WINDOW = 200,
        )
        MemoryDigest.build(older.map { it.role to it.content })
    }
}
```

- `messagesBefore(conversationId, createdAt, id, limit)` 严格早于 `(createdAt, id)`，
  所以取到的是「历史窗口之前」的那一页，不会和窗口本身重叠；
- 只多一次本地查询（200 行、走 `conversationId` 索引），不加网络请求。

### 注入：`PromptAssembler`

`assemble(...)` 与 `assembleGroup(...)` 新增 `memory: String? = null` 参数，
位置固定在**世界书 before 之后、角色定义 / 群成员定义之前**：

```
① system prompt（卡内为空则 ST 默认句）
② 世界书 before 块
②.5 [Earlier conversation] 摘要（memory，做 {{char}}/{{user}} 宏替换）
③ description / personality / scenario（群聊：每个成员的 system/desc/pers/scene）
④ [Example Chat] 示例
⑤ [Start a new Chat]
⑥ 历史（最近 20 条）
⑦ post_history_instructions
⑧ 世界书 after 块
```

`memory = null`（默认值）时输出与改造前**逐条相等**，所以既有 ST golden 对拍断言不受影响。

## 验证

单测（`./gradlew :app:testDebugUnitTest`）：

- `MemoryDigestTest` 7 条：空输入 / 全空白 → `null`；含 `HEADER` 与 `- User:`、`- Assistant:` 标签；
  200 条抽样不超过 `MAX_LINES`；长消息压成一行且以 `…` 结尾；20 条时保留最新的 `m20`；总长有上限。
- `PromptAssemblerMemoryTest` 4 条：摘要位于「世界书之后、角色定义之前」且 role 为 `system`；
  摘要里的 `{{char}}` 会被替换；`memory = null` 与不传时完全一致；
  群聊摘要用全体成员名替换 `{{char}}`。

真机（TAS-AN00 / Android 12 / 1080x2340，会话 10009 条）：

- 打开会话并发一条消息后，`本次请求` 面板第 2 条 system 即摘要：
  `[Earlier conversation]` + 抽样出的旧消息（`#9800` / `#9820` / `#9840` …），1102 字符；
- 摘要位置正确（世界书之后、`Write 梁诗月's next reply…` 之前），历史窗口仍是最近 20 条；
- 截图：`docs/screenshots/beta-5/01-memory-digest.png`、`02-memory-reply.png`。

## 取舍与已知限制

- **抽样而非总结**：模型看到的是「窗口外发生过的若干原句」，不是连贯综述；
  好处是零成本、确定性、可单测，坏处是跨 100 条以上的因果线索仍可能丢。
- **不区分角色**：摘要里 assistant 统一记 `Assistant`（群聊里不写具体是谁），
  避免摘要本身诱导模型模仿「Name: 台词」格式。
- **窗口外只取 200 条**：更长会话更早的部分仍看不到；后续若要覆盖全量，
  应改为「滚动摘要」（把已有摘要 + 新增消息再压一次），需要落库存储，属于 V1 之后的增强。
- 摘要不落盘、不进「导出聊天记录」，只存在于单次请求的 prompt 与调试面板快照里。
