# 16 - V1 正则与变量（Regex & Variables）

## 目标

社区角色卡（尤其带「状态栏」「好感度」「剧情推进」玩法的卡）通常依赖两样东西：

1. **正则替换**：把模型输出的 `[StatusBlock]…` 藏起来、把 `{{user}}` 之类的占位符换成用户名、
   或按规则改写提示词（SillyTavern 里叫 *Regex Script*，分 prompt / display 两种作用域）；
2. **变量**：`{{getvar::好感度}}` / `{{setvar::好感度::10}}` / `{{addvar::好感度::1}}`，
   让卡在不改 prompt 的前提下记住状态。

0.18.0 把这两个能力做成原生实现：**规则与变量都落库、都可在 App 内管理、都走单测**，
不依赖 JS 扩展，也不需要用户手改 JSON。

## 实现

### 数据层（DB v11）

`data/db/Scripts.kt` 新增两个纯新增表（`TeaTalkDatabase.MIGRATION_10_11`，`version = 11`）：

```kotlin
@Entity(tableName = "regex_rules")
data class RegexRuleEntity(
    @PrimaryKey(autoGenerate = true) val id: Long = 0L,
    val name: String,
    val pattern: String,
    val replacement: String,
    val flags: String = "g",
    val scope: String = SCOPE_PROMPT,   // prompt / display / both
    val enabled: Boolean = true,
    val sortIndex: Int = 0,
    val createdAt: Long = 0L,
)

@Entity(tableName = "chat_variables", primaryKeys = ["conversationId", "key"])
data class ChatVariableEntity(
    val conversationId: Long,
    val key: String,
    val value: String,
    val updatedAt: Long = 0L,
)
```

- 变量**按会话隔离**：同一个角色开两条会话，好感度互不影响（符合「剧情线」直觉）。
- 迁移只建表 + `index_chat_variables_conversationId`，不动既有表，老库升级无数据风险。

### 引擎一：`data/RegexEngine.kt`（纯函数）

```kotlin
object RegexEngine {
    fun apply(text: String, rules: List<RegexRule>, promptScope: Boolean = true): String
    fun applyOne(text: String, rule: RegexRule): String
    fun clearCache()
}
```

- `flags` 支持 `i` / `m` / `s`（映射 `RegexOption`）与 `g`（是否全部替换，否则只替首个）；
- 按 `sortIndex` 链式应用，后一条能看到前一条结果（与 ST 一致）；
- 编译缓存 key = `pattern + " " + flags`；
  **坏正则单独用 `broken` 集合记住并跳过**——写错一条脚本不应让整轮对话失败。
  这里踩过一个坑：最初用 `ConcurrentHashMap<String, Regex?>` + `getOrPut`，
  编译失败时 `putIfAbsent(key, null)` 直接抛 NPE，已改为「非空缓存 + broken 集合」两套结构。
- 作用域：`RegexRule.affectsPrompt` / `affectsDisplay` 由 `enabled` 与 `scope` 派生。

### 引擎二：`data/MacroEngine.kt`（纯函数，多轮展开）

```kotlin
class MacroContext(
    val variables: MutableMap<String, String>,
    val userName: String = "User",
    val characterName: String? = null,
    val now: LocalDateTime = LocalDateTime.now(),
    val random: Random = Random.Default,
)

object MacroEngine {
    const val MAX_PASSES = 5
    fun resolve(text: String, context: MacroContext): String
}
```

支持（与 ST 对齐的常用子集）：

| 宏 | 说明 |
| --- | --- |
| `{{getvar::k}}` | 读会话变量，缺失 → 空串 |
| `{{setvar::k::v}}` | 写变量，渲染为空 |
| `{{addvar::k::v}}` | 数值相加；非数值按字符串拼接 |
| `{{user}}` / `{{char}}` | 用户名 / 当前角色名 |
| `{{time}}` / `{{date}}` / `{{datetime}}` / `{{weekday}}` | `HH:mm` / `yyyy-MM-dd` / 两者组合 / 星期 |
| `{{random::a::b::c}}` | 从候选取一个；两个都是整数时按 `[min, max)` |
| `{{pick::…}}` | 同 random，但用会话内稳定种子（同一会话多次解析一致） |

设计取舍：

- **未知宏原样保留**（宁可让模型看到 `{{original}}`，也不静默删掉其它工具的自定义宏）；
- **最多 5 轮展开**：`setvar` 之后同一段文本里的 `getvar` 能读到新值，同时防自引用死循环；
- `MacroContext.variables` 就地读写，调用方解析完只需把「与解析前不同的 key」持久化。

### 接线：`ChatEngine`（prompt 作用域 + 变量落库）

`data/ChatEngine.kt`，在原 `PromptAssembler` 产物之后、发请求之前：

```kotlin
val promptRules = withContext(Dispatchers.IO) { characters.regexRules() }
val variablesBefore = withContext(Dispatchers.IO) { characters.variables(conversationId) }
val macroContext = MacroContext(
    variables = variablesBefore.toMutableMap(),
    userName = userName(),
    characterName = primaryName,
)

val baseMessages = /* PromptAssembler.assemble / assembleGroup */

val messages = if (promptRules.isEmpty()) {
    baseMessages.map { (role, text) -> role to MacroEngine.resolve(text, macroContext) }
} else {
    baseMessages.map { (role, text) ->
        role to MacroEngine.resolve(RegexEngine.apply(text, promptRules, promptScope = true), macroContext)
    }
}

val variableWrites = macroContext.variables.filter { (k, v) -> variablesBefore[k] != v }
characters.putVariables(conversationId, variableWrites)
```

- prompt 规则跑在**每条消息**上，所以卡里的占位符（含 `first_mes`、世界书条目）都会被处理；
- 变量写回必须对比**调用前快照**：早期版本拿同一个 `MutableMap` 比较，永远判定「无变化」，已修；
- 只有存在 prompt 规则时才打 `regex.prompt.apply` 日志，避免正常聊天刷屏。

### 接线：display 作用域（只改显示，不改库）

`ui/chat/ChatScreen.kt`：

- `ChatViewModel.displayRules = repository.observeRegexRules().map { it.filter { r -> r.affectsDisplay } }`；
- 气泡文本统一 `remember(原文, displayRules) { RegexEngine.apply(原文, displayRules) }`，
  三处覆盖：用户气泡、助手气泡、流式气泡；
- 库里存的仍是原文，导出/再入 prompt 不会被 display 规则污染。

### 管理界面：`我的 → 正则脚本`

`ui/regex/RegexRulesScreen.kt` + `RegexRulesViewModel.kt`（`RegexRulesViewModel.factory(app: TeaTalkApp)`，
入口 `Routes.REGEX_RULES = "regexrules"`，`ProfileScreen` 在「世界书」之后插入一行）：

- 列表：名称 + 作用域 + 启停开关，点击进入编辑、右侧删除（二次确认）；
- 编辑器：名称、匹配、替换（留空即删除）、flags、作用域三选、排序、启用，
  底部**预览框**——粘贴一段文本即时看到替换结果，保存前就能判断规则对不对；
- 保存前 `RegexEngine.validate(pattern, flags)`，写错直接提示「规则无法编译：<原因>」，不落库。

- `RegexEngineTest`（11）：大小写不敏感、无 `g` 只替首个、按 `sortIndex` 链式、

## 取舍与已知限制

- **不是完整 JS 脚本引擎**：ST 的斜杠脚本（`/setvar`、`/run`）与 `<% … %>` 条件块不执行，
  只做「正则 + 宏替换」。社区卡里的 JS 块会原样进入 prompt（这正是 0.18.0 之前的行为，未退化）。
- **变量是字符串**：`addvar` 只在两侧都能解析成数字时做加法，否则拼接；
  没有类型系统，也没有数组/对象（ST 的 `{{getglobalvar}}`、`{{getvark}}` 未实现）。
- **不区分全局变量与会话变量**：目前只做会话级，够覆盖「剧情状态」，但跨会话共享（全局好感度）还要再加一列或一张表。
- **未知宏保留**：如果卡作者写错宏名，模型会看到 `{{xxx}}` 原文；这是刻意的（避免吃掉其它工具的宏），
  但也意味着「写错不报错」，只能靠预览框自查。
- display 规则只作用于聊天页气泡，**不影响**导出的 jsonl、备份与 prompt 面板快照。
