## 3 已知缺口（不阻塞 M1 关闭）

1. **HTTP 状态码未展示**：401/429 有专属文案；其它 4xx/5xx 统一 `Server returned an error`。后续在 `ChatError.HTTP` 里带 `code` 即可（改 strings + UiText）。
2. **429/超时/断流未实测**：本次只实测了 404（httpbin）。断流可后续用开关「模拟断流」或本地 mock 验证。
3. **真机未回归**：本步骤只在 AVD 验证；真机（HarmonyOS 4.2 / API 31）留一次回归。
4. **prompt 仍是单条 system + 最近消息**：世界书扫描、宏、预算裁剪尚未接入（M2/M3）。

## 7 P1 修复轮（2026-10-27，0.3.2）

四专家审阅（`docs/reviews/m1/01-汇总与修复清单.md`）给出的 10 条 P1 本轮全部处理，另附带 3 条同批小修。

| # | P1 | 修法 | 验收 |
| --- | --- | --- | --- |
| 1 | API Key 尾 4 位进日志/诊断导出 | `SecretStore.put()` 只记 keyLen，删掉 `tail=` | `grep -r 'tail'` 仅剩注释；导出文件无尾号 |
| 2 | 未配置模型被误报为「未配置供应商」 | `ProviderRepository.resolve()` 改 `sealed interface ProviderResolution { Ok/NoProvider/NoKey }`（原全返回 null）；`ChatEngine` 细化 `NO_MODEL` | 未配 provider/未配 key/未填模型三种文案分别正确 |
| 3 | `NO_MODEL` 仍写入一条用户消息 | 新增 `ChatEngine.preflightError()`（不落库），`ChatViewModel.send()` 先判后发；失败把原文回填输入框 | 模拟器实测：无消息入库（DB count 0）、输入框保留文案、横幅可重试 |
| 4 | 403 与 401 混为一谈 | 403 走 `ChatError.HTTP(403)`；单测 `403 is not zeroed into unauthorized` | 单测通过；文案为 `HTTP 403` |
| 5 | 停止后可能写回半截/卡住 | `generation` 代次 + `stop()` 先 `cancel` 后 `join` 再落库；`ChatScreen` 状态改为状态机（streaming/error/notice） | 实测点停止 → `Generation stopped`、5 秒后无追加文本，半截已入库 |
| 6 | 向上翻历史时新 token 把列表拽回底部 | `stickToBottom` 派生状态：只有最后一项可见时才自动跟随 | 长回复上翻后不再被拉底（实机手测） |
| 7 | 长回复在窄气泡里看不全、无法复制 | 气泡 `widthIn(max = 268.dp)`；长按弹「消息预览」+ 复制 | `docs/screenshots/m1-p1/01-preview-dialog.png` |
| 8 | 流中途 `{"error":...}` 帧被当成空回复 | `ChatClient` 检测 `error` 字段 → `Failed(HTTP 200)` 带 detail；单测 `mid stream error frame surfaces as failure` | 单测通过 |
| 9 | `finish_reason=length` 静默截断 | `ChatEvent.Completed(truncated)`；截断时弹「回复可能被截断，点重试继续」 | 单测 `finish reason length marks truncated` |
| 10 | 键盘弹出后输入框被遮挡 | 输入条 `WindowInsets.ime.union(navigationBars)`；错误横幅在输入条上方 | 模拟器 + 真机均验证 |

同批小修：`FileLogSink` 补 3 条单测（写入/开关/2MB 轮转）；`Diagnostics` 导出前清理 `cache/diagnostics` 旧文件（只留最近一次）；`ErrorBanner` 文字 `weight(1f)` + `TextButton` 点击区（长文案不再把按钮挤成 14dp）。
