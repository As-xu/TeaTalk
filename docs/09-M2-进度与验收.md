## 2. 数据模型（DB v4）

`messages` 新增三列（`MIGRATION_3_4`，纯增量，存量行为不变）：

| 列 | 类型 | 语义 |
| --- | --- | --- |
| `variantsJson` | TEXT NOT NULL DEFAULT '[]' | 同一轮回复的所有候选，JSON 字符串数组；`[]` 视为只有一个版本 |
| `selectedVariant` | INTEGER NOT NULL DEFAULT 0 | 当前选中下标 |
| `status` | TEXT NOT NULL DEFAULT 'complete' | `complete` / `stopped` / `failed` |

约定：`content` 永远是 `variants[selectedVariant]` 的**镜像** —— 聊天列表预览、prompt 历史都读 `content`，老代码零改动。

新增 `data/MessageVariants.kt`（`of/parse/encode`，老数据兜底 + 坏 JSON 兜底）与 5 条单测。

## 3. 行为改动

- **引擎不再落库**：`ChatEngine.streamReply()` 只负责流式事件；由 `ChatViewModel` 在完成/停止/失败时调用
  `CharacterRepository.appendAssistantReply(characterId, text, status)`。
- **追加还是新消息**：如果最后一条是 assistant，就作为新版本追加（返回该消息 id）；否则插入新消息。
- **重试**：`retry()` 用 `streamReply(excludeLastAssistant = true)` —— 把正在重试的那条回复从 prompt 历史里剔除，
  避免模型看到自己上一版被带跑；结果作为新版本追加。
- **切换版本**：气泡下方 `‹ n/m ›`，点箭头 → `repository.selectVariant(id, index)`，同时更新 `content` 镜像与 `selectedVariant`。
- **删除**：长按气泡 → 弹层「重试 / 删除 / 关闭 / 复制」→ 删除走二次确认对话框。
- **状态**：停止 → `stopped`；流式失败 → 已收到的半截以 `failed` 落库（便于以后「重试失败消息」）。
