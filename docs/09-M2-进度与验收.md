### 数据层（DB v4）

- `messages` 新增三列：`variantsJson TEXT NOT NULL DEFAULT '[]'`、`selectedVariant INTEGER NOT NULL DEFAULT 0`、`status TEXT NOT NULL DEFAULT 'complete'`。
- `content` 语义：当前展示文本 = `variants[selectedVariant]` 的镜像。

### 行为

- 发送：先插入 user 消息，再流式生成；首包失败时删除空 assistant 消息（不留空泡）。
- 停止：已生成部分落库，`status=stopped`。
- 重试：向该回复追加新版本（不重新发 user 消息），自动切到新版本。
- 切换：气泡下 `‹ Version i of n ›`，点箭头切换并持久化 `selectedVariant`。
- 删除：长按 → 预览弹层 → Delete → 二次确认（提示版本数）→ 删除整条消息及全部版本。

- 删除确认显示 `This reply has 2 versions...`，取消/删除均正常。

## 步骤 2a：变体级状态（B1，DB v5）

### 为什么

审阅指出：`messages.status` 是消息级，但一条气泡可承载 N 个候选版本，无法表达“第 2 版是停止/失败生成的”。用户切到失败候选时也看不到任何解释。

### 实现

- `messages` 新增 `variantStatusJson TEXT NOT NULL DEFAULT '[]'`（与 `variantsJson` 等长；空数组按 complete 补齐）。
- `MessageVariants` 新增 `statuses()/parseStatuses()/encodeStatuses()/append()`；追加新版本时同时追加其状态。
- 重试/停止/失败落库时写入对应版本状态；`selectVariant` 同步消息级 `status`。
- UI：变体条显示 `Version 2 of 2 · Stopped`；单版本但状态非 complete 时也显示 `Stopped`/`Failed`（无箭头）。
- 迁移 `MIGRATION_4_5`（纯增量），已在存量 v4 数据库上实测升级成功（logcat `db.migrate from=4 to=5 ms=1`）。

### 验证

- 注入 `variantStatusJson=["complete","stopped"]` → 截图显示 `Version 2 of 2 · Stopped`。
- 真实生成中停止 → 新消息显示 `Stopped`（单版本）。
- 测试：app 新增 3 条 `MessageVariantsTest` 状态用例（合计 64 条全绿）。

### 仍未做（B1 剩余）

- 变体条上的“每版状态点”（当前只显示选中版本的文字状态）。
- 迁移测试（B6）仍未补。

## 步骤 2b：Provider 切换兜底（B2，DB v6）

### 为什么

切到另一个接口后，旧消息由旧接口生成：既可能因为旧 key 失效而“黑气泡”，用户也看不出这条是谁生成的。审阅列为 UX P0。

### 实现

- `messages` 新增可空列 `providerId / providerName / model`（`MIGRATION_5_6`，纯增量；老消息为 null 不显示提示）。
- `ChatEngine.activeProvider()` 暴露当前生效接口；`ChatViewModel` 在发送/重试前捕获，完成/停止/失败落库时写入来源。
- UI：回复来源与当前接口不同时，气泡下显示 `Generated with <name> · <model> (not the current provider)`（中文同理）。
- 老消息（M2 之前/本次迁移前）不显示提示，避免噪音。

### 验证

- AVD：发送 → DB 记录 `providerId/providerName/model`；切到另一个 Provider 后重进会话 → 旧回复出现来源提示；新回复无提示。
- 迁移：存量 v5 库升级到 v6 成功（logcat `db.migrate from=5 to=6 ms=16`）。

### 仍未做

- 提示目前是纯文本，不能点击“用当前接口重试”（入口仍在长按菜单的重试）。
- Provider 被删除时无法区分“已删除”与“仅切换”，只显示名称。

## 步骤 3：Markdown 渲染（0.6.0）

### 为什么手写而不是引库

- 需求只有“把模型输出里常见的 Markdown 渲染成可读气泡”，不需要图片、脚注、表格、跳转；
- 流式输出每 60ms 变一次，必须容忍未闭合标记（`**`、``` 没收尾时按字面显示），第三方渲染器普遍在解析失败时整段退回纯文本；
- 手写解析是纯 Kotlin，可在 JVM 单测里覆盖，不进 Android 依赖。

### 覆盖范围

- 块级：`#/##/###` 标题、段落合并、`-/*/+` 无序列表、`1.` 有序列表（保留起始号）、`>` 引用（左侧竖条）、``` 代码块（语言标签 + 等宽 + 底色）、`---` 分隔线。
- 行内：`**粗**`、`*斜*`、`` `代码` ``、`~~删除线~~`、`[文字](链接)`（下划线着色，暂不跳转）；`\` 转义。
- 未支持（按普通文本渲染）：表格、HTML、脚注、嵌套列表、图片。

### 实现位置

- `app/src/main/java/com/teatalk/xs/ui/components/Markdown.kt`：`Markdown.parse`（块级）+ `Markdown.inline`（行内，返回纯文本与 span 区间）+ `MarkdownText` Composable。
- `ui/chat/ChatScreen.kt` 的 `AssistantBubble` 改用 `MarkdownText`；用户气泡、长按预览弹层保持纯文本（复制友好）。
- 流式与历史消息共用同一渲染路径；role-play 的 `*动作描写*` 会被渲染为斜体。

### 验证

- 单测 11 条（`MarkdownTest`）：标题/段落合并/两种列表/代码块含空行/未闭合代码块/引用与分隔线/五种行内/未闭合行内/转义/相邻 span 合并/星号动作。
- AVD 实测：模型输出的 `#`、`-`、`>`、```` 正确渲染（截图 `docs/screenshots/m2-md/01-blocks-dark.png`）；`**bold** *italic*` 显示为粗体+斜体（`02-inline.png`）。
- 性能：文本每变一次重解析，5KB 内未见掉帧；后续如需可加“流式中按段落缓存”。

### 已知取舍

- 长按预览弹层仍是纯文本（便于复制原文）。
- 表格等复杂结构退化为普通行文本。
