# 23 - 多源降级（0.23.0）

## 目标

一个接口挂掉（限流、超时、服务端 5xx）时，不要让整轮对话白等：按用户配置的备用链自动换接口重试，同一条消息继续出字。

## 范围取舍

只做「单次请求内的顺序降级」，不做连接池 / 竞速 / 健康度统计：

- 备用链存 `AppPrefs`（有序 id 列表），**不建新表**：链的长度通常 1–3 个，不需要关系模型；
- 只对「换一个接口可能就好了」的错误切换：429 / 408 / 5xx / 超时 / 断网 / 流内服务端错误 / 200 但空 body 或没有终止事件（坏中转的典型症状）；
- 401 / 400 / 403 / 404 / 缺 key / 缺模型属于配置问题，换接口只会重复失败，直接报错；
- 主接口不参与备用选择（弹层里不列出）：它在尝试顺序里永远排第一，勾进去只会让「备用 N」错位；
- **已经吐出内容后不再切换**：两条回复会拼进同一条消息，比直接失败更糟。

## 交互

| 步骤 | 行为 |
| --- | --- |
| 配置 | 我的 → 模型与接口 → 右上角 ⇅ →「备用接口」勾选（可多选，顺序 = 列表顺序） |
| 列表提示 | 未配置：「未配置备用接口：主接口失败时直接报错」；已配置：「已配置 N 个备用接口，按列表顺序尝试」 |
| 行内标记 | 被设为备用的接口显示「备用 1 / 2 …」小标签 |
| 触发降级 | 主接口失败后气泡上方 Snackbar：「LocalStub 暂时不可用，已切换到 DeepSeek」 |
| 结果 | 备用接口正常流式出字；气泡下方来源标签显示实际生成接口 |
| 清理 | 删除接口时自动从备用链移除；全部取消勾选即关闭降级 |

## 实现要点

- `data/FallbackPolicy.kt`（新增）：纯函数。`isRetryable(ChatError)`、`order(primaryId, fallbackIds)`（主接口在前、去重、跳过空 id）、`shouldContinue(error, producedText, remaining)`。
- `data/model/AppPrefs.kt`：新增 `fallbackProviderIds: List<String>`，以逗号分隔存 `fallback_provider_ids`；读取时去空、去重；写空列表即删除键。
- `data/net/ChatClient.kt`：`ChatEvent` 新增 `Fallback(fromProviderName, toProviderName)`（由引擎发出，client 不产生）。
- `data/ChatEngine.kt`：
  - 构造新增 `fallbackProviderIds: () -> List<String>`；
  - `resolveChain()` 把「主接口 + 备用」解析成可用候选列表，跳过被删/缺 key 的槽位，记下主接口的失败原因；
  - `stream()` 的 provider 解析改为候选链；prompt / 世界书 / 正则 / 宏只构建一次（与接口无关），随后对每个候选循环：采样解析 → `PromptDebugStore.publish` → `Started` → `client.stream(...)`；
  - 失败且 `FallbackPolicy.shouldContinue(...)` 为真时打 `chat.fallback from= to= reason= attempt=` 并 `emit(Fallback)`，否则 `emit(Failed)`；
  - `preflightError()` 改为「链里任一候选有模型就算通过」。
- `ui/chat/ChatScreen.kt`：`collectStream` 处理 `ChatEvent.Fallback` → Snackbar（`chat_fallback_switched`，两个参数：从 / 到）。
- `ui/providers/ProvidersViewModel.kt`：新增 `fallbackIds` 状态与 `saveFallback(ids)`；删除接口时从链里清理（`notify = false`）。
- `ui/providers/ProvidersScreen.kt`：顶栏 ⇅ 入口 + 勾选弹层（排除当前主接口；确认时按 provider 列表顺序落库，保证界面上的「备用 N」与实际尝试顺序一致）。
- `ui/chat/ChatScreen.kt` 的来源标签：`activeProviderId` 始终是「配置里的主接口」，降级生成的消息因此能显示「由 X 生成，与当前接口不同」。
- 文案：`res/values/strings.xml` 与 `values-en/strings.xml` 各新增 8 条（`chat_fallback_switched`、`providers_fallback_*`）。
- 单测：`app/src/test/java/com/teatalk/xs/data/FallbackPolicyTest.kt`（5 个用例、覆盖 15 种决策组合）。

## 已知限制

- 每次请求都从主接口开始：不会记住「上次成功的接口」，也不会做接口健康度统计。
- 不做并行竞速：第一个接口失败（连接超时 20s）后才会尝试下一个，最坏等待 = 各接口超时之和。
- 401 / 400 / 403 / 404 不切换：这属于配置错误，换接口没有意义；用户需要自己改配置。
- 已经输出内容后失败不切换：避免两条回复拼成一条；此时可手动「重试」（重试会重新走降级链）。
- 备用链只对 OpenAI 兼容的 `/chat/completions` 生效；翻译接口（`translationProviderId`）不走降级链。
- 降级只发生在「本次回复」内；上一轮已落库的半截回复不会被自动清理。
- 降级循环没有引擎级单测（`ChatClient` 是 final class，需要先抽接口），当前由纯函数单测 + 真机日志覆盖。
