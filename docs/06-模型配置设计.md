# 模型配置（多 Provider）设计

> 状态：**已规划，未实现**。M1 只落最小可用（单配置），但表结构与 UI 预留多配置，后续加字段不迁移痛苦。
> 用户要求（m02750）：模型配置是 App 的一个设置项，用户自定义源，可配置多个，随时切换。

## 1. 目标与不目标

**目标**
- 用户在「我的 → 模型与接口」里增删改任意 OpenAI 兼容源（DeepSeek、OpenRouter、LM Studio、ollama、本地网关…）
- 同时保存多套配置，随时切换（全局默认 + 会话级覆盖）
- API Key 只进加密存储，不进日志、不进备份、不显示明文

**不目标（M1/M2 明确不做）**
- 非 OpenAI 兼容协议的原生适配（Anthropic / Gemini 原生 API）→ M3，通过 `apiFormat` 字段扩展
- 多 key 自动轮换 / 按量计费统计 → 后续
- 云同步配置

## 2. 数据模型

```kotlin
// :core 领域模型（不含 Android 依赖）
data class ModelProvider(
    val id: String,                 // UUID，稳定主键
    val name: String,               // 用户可见名，如「DeepSeek 官方」
    val apiFormat: ApiFormat,       // OPENAI_CHAT（M1 唯一实现）
    val baseUrl: String,            // 必须 https（局域网 http 需用户显式允许）
    val defaultModel: String,       // 如 deepseek-chat
    val models: List<String>,       // 拉取缓存，可空
    val params: ModelParams,        // 见下
    val createdAt: Long,
    val lastUsedAt: Long,
)

data class ModelParams(
    val temperature: Double = 1.0,
    val topP: Double = 1.0,
    val maxTokens: Int? = null,     // null = 服务端默认
    val contextWindow: Int = 8192,  // 用于 prompt 预算
    val stream: Boolean = true,
)
```

存储（Room，`teatalk.db`）：

| 表 | 字段 | 说明 |
| --- | --- | --- |
| `model_providers` | `id TEXT PK`、`name`、`api_format`、`base_url`、`default_model`、`models_json`、`params_json`、`created_at`、`last_used_at` | 一行一套源；`api_key` **不在这张表** |
| `chats` | 新增 `provider_id TEXT NULL` | 会话级覆盖；NULL = 用全局默认 |
| `app_settings` | `active_provider_id TEXT NULL`、`logging_enabled INT` 等 | 单行 KV 表（M1 新建） |

密钥：`EncryptedSharedPreferences`（`MasterKey` AES-256-GCM，AndroidX Security）键名 `provider_key_<id>`；UI 只回显 `sk-…abc4`（后 4 位）。卸载即失效，`allowBackup=false` 已保证不进云备份。

## 3. UI 结构

```
我的
└── 模型与接口
    ├── 当前使用：DeepSeek 官方 · deepseek-chat        ← 点进去切换默认
    ├── [+ 添加配置]
    └── 配置列表
        ├── DeepSeek 官方        deepseek-chat    ○ 默认   ⋮
        ├── OpenRouter          claude-3.5        ⋮
        └── 本地 LM Studio      127.0.0.1:1234    ⋮
```

- 添加/编辑页字段：名称、Base URL、API 格式（M1 仅 OpenAI 兼容）、API Key（密码框 + 显示切换）、模型（「拉取列表」按钮 + 手填）、高级参数（temperature/topP/maxTokens/上下文）
- 行内菜单：设为默认、测试连接、复制、删除
- 「测试连接」= `GET /models` 或最小 chat 请求，10s 超时，结果就地显示（成功 + 延迟，或错误码 + 原因）
- 会话级切换（M1 后期/M2）：聊天页顶栏 → 详情面板 →「本次会话模型」

## 4. 运行期选择链路

```
ChatViewModel.send()
  → ProviderRepository.resolve(chatId)         // chat.provider_id ?: settings.active_provider_id
  → ModelProvider + 解密 apiKey
  → ChatCompletionClient (OkHttp + SSE)        // M1: /chat/completions, stream=true
  → 流式增量回填 UI，落库 message
```

失败兜底：401（key 无效）/ 404（模型名错）/ 429（限流，提示稍后）/ 超时（可重试按钮）/ 断流（保留已收内容并标记未完成）。

## 6. 验收（M1 最小集）

- 添加 2 套配置，各自测试连接成功；切默认后新会话生效
- 用真实 key 流式出字（SSE 分段渲染，不一次性弹出）
- 401 / 超时 / 断流三种错误有明确提示，且不崩
- `grep` 代码与 logcat：任何位置都搜不到明文 key

## 7. 已确认（2026-10-26，用户 m02775）

1. **明文 http：默认禁止**。允许用户在「高级」里打开「允许明文连接（仅本机 / 局域网）」开关，开关开启时展示风险提示（局域网内可被嗅探）；`baseUrl` 默认校验 `https://`，白名单 `127.0.0.1`、`localhost`、`10.*`、`192.168.*` 可在开关打开时放行。
2. **导入 SillyTavern API 配置：要做，排在 M2**（迁移功能：读 ST `settings.json` 的 `main_api` / `api_url_*` / `api_key_*` 等字段，转成 `ModelProvider` 行；匹配不到的字段给「手动补全」提示）。
